## ترتيب التطبيق اللاحق

1. تثبيت بصمات المصدر ولقطة الهدف المحدثة، ومراجعة نطاق الحقول والدفعات المطلوبة. جميع مقترحات التجهيز `readyToApply: false`؛ أوسمة `REFERENCE_DATA_IMPORTED` و`NEEDS_MANUAL_REVIEW` في الملف ليست موافقة استيراد.
2. الحفاظ على الدول والعملات واللغات الموجودة. مراجعة اختلافات السجلات الأربعة فقط إذا كان تحديثها مقصودًا؛ لا منع بقية الإضافات السليمة بسبب اختلاف اسم واحد.
3. مراجعة وإنشاء المناطق عبر `ReferenceDataUseCases.upsertRegion` الذري مع Audit/Outbox. عقد الاستيراد العام لا يملك نوع REGION؛ لا اختلاق إيصال P6/P7 أو استخدام إدخال SQL مباشر.
4. حفظ نتائج المناطق بمعرّفاتها الحقيقية، ثم إعادة حل روابط المدن بالدولة والمنطقة داخل نفس نطاق الدولة. `regionId` و`cityId` في CSV معرفات مصدر، ولا تتحول إلى مفاتيح قاعدة مخمّنة.
5. إدخال المدن عبر أصل مفحوص ثم screening ومعاينة ومراجعة وتطبيق لدى مالك المراجع. التحديثات تستخدم ID الفعلي والإصدار المتوقع. لا أداة seed أو حذف أو تغيير حياة سجل من علم الملف.
6. مقارنة الأعداد والهويات والعلاقات والإيصالات بعد كل دفعة، واختبار الإعادة دون تكرار والاستئناف بعد الانقطاع. النسخ ودليل الاستعادة على مستوى الدفعة المتأثرة، لا نسخ كامل لكل مدينة. أي تغير مصدر أو إصدار هدف يستوجب معاينة جديدة.
