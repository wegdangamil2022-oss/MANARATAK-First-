## الإصلاحات المنفذة

1. **معاملة علاقات الدورة داخل أمر المالك:** كان `PrismaCourseRelationshipRepository.withTransaction` يربط Prisma transaction client، ثم يحاول الرفض أو reconciliation استدعاء `$transaction` عليه رغم أن Prisma لا يدعم المعاملات المتداخلة. أثبت التشغيل `TypeError: this.prisma.$transaction is not a function`. صار المستودع ينفذ العمليات ضمن معاملة المالك القائمة، ويبقي المعاملة المستقلة عند استعماله من الجذر. أصبحت علاقة الرفض وإبطال الإسقاط ونسخة المالك وaudit/outbox قابلة للالتزام أو التراجع معًا.
2. **تغيّر مصدر الإسقاط:** كانت `upsertMajorProjection` تحفظ APPROVED عند استبدال دليل المصدر. أصبحت إسقاطات TAXONOMY_MAPPING تدخل REVIEW_REQUIRED عند تغير profile/taxonomy/source link/source mapping/type/relationship؛ لا يعاد اعتمادها تلقائيًا. تبقى العلاقات المستقلة المحفوظة.
3. **التخصص غير المنشور:** كان فلتر دورات التخصص يعيد دورة approved mapping حتى بعد تحول التخصص إلى DRAFT أو ARCHIVED. صار شرط التخصص PUBLISHED جزءًا من SQL قبل الصفحة والعدد.
4. **فلتر أكاديمي غير مدعوم:** كان CoursePublicRouter يقبل degreeLevelId/profileId ويتجاهلهما، فيعيد200 ونتيجة غير مفلترة. صار query صارمًا ويرفضهما400. تظل القائمة العامة للتخصص تسمح بعلاقة بلا profile، دون استنتاج درجة من نص مستوى التدريب.
5. **ادعاء إداري غير مثبت:** أزيل النص الذي يزعم أن غياب روابط الجامعات يعني إتاحة المنحة في جميع الجامعات الحكومية؛ أصبحت الحالة الفارغة تصرح بغياب جامعات/برامج موثقة. هذا تصحيح نصي محدد، وليس إكمال عقد عرض الأزواج في الإدارة.

الملفات الأساسية: `packages/infrastructure/src/courses/PrismaCourseRelationshipRepository.ts`، `apps/api/src/presentation/api/router/CoursePublicRouter.ts`، `apps/admin/src/pages/ScholarshipCatalogDetailPage.tsx`، مجموعتا PostgreSQL الجديدتان وإعداداتهما. لا schema أو migration جديدة ولا تغيير سياسة نشر: البنية المنشورة ما زالت تتطلب unpublish أولًا، واختُبر unpublish الحقيقي ثم الرفض.

## البيئة والعوائق التي عُزلت

PostgreSQL16 بالـdigest المثبت، Node22.16.0، Prisma5.22.0 المشروع. الإعداد بدور migration محدود والاختبارات بدور post28_app. لكل تجميد قاعدة جديدة باسم عشوائي وOID وnonce وmarker وrun وSHA؛110 checksums وparity ناجحة. لا DDL للتطبيق ولا كتابة ledger ولا توسيع grants بهذه الجولة.

منع Docker إنشاء حاويات جديدة بسبب امتلاء address pools ثم ENOSPC. أضيف subnet داخلي محدود/28 للحاويات الجديدة دون تعديل سياسة Docker العامة. ولعائق القرص، أصبح للأداة الرسمية خيار parent state صريح: يتحقق من حاوية محلية disposable تعمل، بالصورة المثبتة والشبكة الداخلية وtmpfs، ثم ينشئ **قاعدة جديدة** على ذلك الخادم، دون إعادة ربط قاعدة أو عقد قديمين أو حذفهما أو تعديل الأدوار القديمة. عقود القواعد الأربع وأرقام OID المختلفة محفوظة. مصدر أداة الإنشاء `scripts/database/post28-new-transaction-target.mjs` موثق وحُرس بالسياق والصلاحية/profile وبفحص parent مزور قبل Docker.

هذا عزل قواعد على خادم مؤقت مشترك، وليس خوادم مستقلة أو دليل crash durability أو recovery أو R03 instance جديدة. تبقى tmpfs محدودة768MiB في حاوية2GiB، ولا تستخدم لإغلاق R05/R10. بقيت جميع القواعد/الحاويات/الـvolumes السابقة محفوظة.

رفض Vite جمع المجموعة أولًا لأنه كتب ملف config مؤقتًا عبر symlink dependencies على القرص الممتلئ: صفر حالات منفذة. نُسخت dependencies المثبتة دون تغيير إلى نسخة العمل المؤقتة، ثم أعيد التشغيل على SHA/run نفسيهما. نُقل كاش Node22 نفسه إلى /tmp مع إبقاء مساره symlink، دون تغيير الإصدار. هذه حوادث بيئة لا نجاحات اختبارات ولا عيوب منتج. العقود والأسرار والسجلات الخام خارج Git.

## ما يمنع الإغلاق الحقيقي

- **R05:** مراجعتا assets/student غير متوفرتين لحزمة known-source؛ لم ينفذ lifecycle ثم109→110 والتوافق والانقطاع/الاستئناف. توجيه متابعة R06 ليس إعفاءً من تلك البوابة.
- **DEC06:** حماية nullable uniqueness المتزامنة ليست مثبتة على مستوى PostgreSQL. يلزم تصميم ومراجعة التكرارات وmigration جديدة ببوابات R04/R05 المناسبة؛ لا تغيير تاريخي أو تجاوز لقبول110.
- **الوثائق/التخزين:** سحب رابط سبق تسليمه ودورة الوثيقة مع خدمة تخزين فعلية ما زالا غير مثبتين بالكامل.
- **المالية والشهادات:** لا نجاح لدى payment/refund/settlement provider حقيقي، ولا سلطة/template معتمدان ودورة إصدار/تحقق/إلغاء كاملة للشهادة. لا استبدالها ببيانات synthetic أو mock.
- **باقي العلاقات:** عقد وإسقاط أزواج المنحة في صفحة التفاصيل والإدارة، وفصل بلدان الدراسة/الأهلية/التمويل، وتطابق لغة البرنامج، وowner publication/import crash recovery والمصفوفة متعددة الصفحات والمتصفح، ما زالت تحتاج الإكمال المحدد.
