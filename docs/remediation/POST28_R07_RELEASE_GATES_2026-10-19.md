# R07 — فحوص القبول وتجهيز هدف Linux للمراجعة

**نجحت حالات symlink الأربع على Linux. بقي القبول الرسمي مفتوحًا؛ CI المصحح في طابور GitHub، واسترجاع حزم الإصدار وفحص صورة Linux لم ينفذا بعد.**

مرشح التنفيذ الحالي `8be720a65678d61eb8076f08177c5dc911c54c6d` على `feat/post28-r07-artifact-preparation`. [التشغيل الذي يجب استكماله](https://github.com/wegdangamil2022-oss/MANARATAK-First-/actions/runs/39278772529) قائم بالفعل؛ لا حاجة لإنشاء تشغيل آخر ما لم يتغير المصدر أو يثبت سبب لإعادة الجزء الفاشل. عند حفظ هذه الدفعة كانت المهام الأربع `queued` دون مشغّل مسند. لم تعرض الخدمة سبب الانتظار، فلا ننسبه إلى الفوترة أو عطل عام بلا دليل.

## ما أُنجز

كان Enterprise CI يعمل عند الدفع إلى main/develop فقط، ولذلك لم يكن نجاح Vercel على فرع الإصلاحات دليلًا على CI الكامل. أضيف الفرع الموحد إلى مشغّل CI الحالي مع إبقاء قيود الترقية والنشر والتوقيع كما هي. لم يُنشأ طلب دمج أو يُدمج main.

أضيفت حالات التغليف الثابت الأربع إلى فحوص المصدر على Ubuntu. أثبت سجل التشغيل `39277252905` على المصدر `5b9c4e4502d2ea9168e223a4f2a465ef799b6662` رفض رابط ملف JavaScript، ورابط المجلد الأب، ورابط metadata، ومدخل symlink قبل tar. هذه حالات PASS محددة؛ التشغيل نفسه فشل لاحقًا في تجهيزات Section27، فلا يتحول نجاحها إلى PASS كامل له. لم تتغير سياسات التغليف أو شروط هذه الاختبارات لإظهار النجاح.

أُصلحت عوائق CI التي ظهرت بالتتابع:

| السبب المثبت | الإصلاح |
|---|---|
| جرد البيئة لا يطابق مصادره بعد إضافة إعداد الاسترجاع | إعادة توليده بالأداة الرسمية؛ 321 اسمًا، بلا قراءة قيم الأسرار |
| الترحيل111 غير مسجل في سياسة الاستعادة العامة | إضافة `BACKUP_RESTORE_REQUIRED`؛ منع إسقاط قيد التفرد الأقوى أو حذف الصفوف بوصفه تراجعًا. لا تغيير SQL تاريخي أو مخطط Prisma |
| فاحص الاستيرادات يعامل حاضنات الأدلة المنسوخة من مختبر خارجي ككود يعمل من مكان الأرشفة | استثناء النسخة المؤرشفة فقط بعد مطابقة SHA المصدر ومسار الملف وحجمه وSHA256 مع فهرسها. النسخ غير المفهرسة أو المعدلة تفشل؛ استيرادات الكود الفعلي تظل مفحوصة |
| فاحصا W9 والدورات يطلبان مجانية الشهادة القديمة | مطابقتهما مع DEC‑03 المعتمد: الدراسة المجانية إلزامية للدورة المستوردة، وتكلفة الشهادة مستقلة. يبقى إثبات المصدر واللغة والرابط والمالك الحالي مطلوبًا |
| ثلاث تجهيزات Section27 لا تمثل عقود المالك الأحدث | استكمال `testId` للإصدار المنشور، واستعمال دالة القراءة المنشورة، ومحاكاة معاملة snapshot مع تأكيد `RepeatableRead`. لم تُضعف شروط الإخفاء أو SQL أو رفض الصلاحيات |

هذه إصلاحات تشغيل CI والفاحصات والتجهيزات؛ لا تغيير جديد في سلوك API/Web/Admin في هذه الدفعة. فحوص قاعدة البيانات والمتصفح السابقة محفوظة بمصادرها الأصلية، ولم تُكرر أو تُنسب إلى المرشح الجديد.

## استرجاع الحزم وهدف الاستضافة

أضيفت مهمة مستقلة تسترجع حزم API/Web/Admin من مخزن GitHub Actions المستخدم أصلًا في CI، إلى مجلد جديد في مشغّل منفصل. تتحقق من اسم الحزمة الذي يجمع run وSHA، ثم بصمة manifest المحفوظة مستقلًا في خرج مهمة البناء، وبعدها بصمات وأحجام الوحدات وSBOM. تبقى المهمة مشروطة بنجاح المصدر؛ **لم تنفذ استعادة حزم الإصدار بعد**. استُرجع تقرير CI صغير بالفعل وقرئت محتوياته للتحقق من الفشل؛ استرجاع التقرير لا يفي ببوابة استرجاع وحدات الإصدار. لا اعتماد لمخزن إنتاج طويل الأجل أو سياسة احتفاظ إنتاجية مستنتج هنا.

بناءً على اختيار المالك، جُهز هدف **Linux x64 / Node22 / PostgreSQL16 للمراجعة**. [Dockerfile](../../config/release/linux-x64/Dockerfile) و[فاحص الصورة](../../scripts/release/post28-linux-image-probe.mjs) موصولان بمهمة CI بعد استرجاع الحزم. يبدأ التجهيز من تثبيت Linux إنتاجي جديد وفق lockfile ومن الحزمة المسترجعة، ثم يثبت بصمة صورة Node الأساسية ويبني صورة بمستخدم `node`. الفحص مصمم لتحميل محرك Prisma والاعتماديات الفعلية داخل حاوية بلا شبكة وبنظام ملفات للقراءة فقط، دون capabilities أو صلاحية root، ولإثبات إصدار صورة PostgreSQL16 دون بدء خادمها. لا يرفع صورة إلى registry.

**هذا مسار مجهز لم يُنفذ بعد؛ لا صورة Linux مثبتة البصمة ولا native PASS مُدّعى الآن.** كما أنه لا يثبت إقلاع API أو اتصاله بقاعدة Linux أو graceful drain أو صلاحية إعدادات الإنتاج. هذه تحتاج حاضنة استضافة اختبار معتمدة وإعداداتها الفعلية، ثم تشغيلًا معزولًا مصرحًا به؛ لا تُخترع أسرار أو مزودات لإرضاء جاهزية الإنتاج. ملف Compose التطويري القديم وبيانات PostgreSQL15 المحتملة لم تُعدّل أو تُرقَّ آليًا.

## الفحوص وحدود النتيجة

محليًا: 9 اختبارات عقود CI، و4 للاستعادة، و7 لتنظيم المستودع تشمل رفض العبث بالأرشيف، و9 لبوابة نشر الدورات، و24 بندًا لفاحص الدورات، ثم إعادة الحالات الثلاث الفاشلة فقط في Section27؛ نجحت في نطاقها. هذه أعداد مجموعات منفصلة لا نسبة قبول شاملة. فشل محلي استقصائي في تجميع W16 سببه غياب bash على Windows؛ لم يُعد تعريفه PASS، وكان W1 قد اجتاز Linux CI. فاحص P5 القديم غير الموصول بمسار CI يحتوي توقعات قديمة؛ لم يُحذف ولم يُستخدم قبولًا، والتعديل الاستقصائي عليه أُرجع.

لم يُعَد بناء محلي أو متصفح أو مختبر PostgreSQL أو مجموعات R05/R06. تشغيل CI الشامل على SHA مصحح هو المطلوب الجديد؛ كل محاولة سابقة أُتبعت بتحليل سببها قبل الدفع التالي. [سجل المحاولات](../reviews/evidence/post28/8be720a65678d61eb8076f08177c5dc911c54c6d/r07-release-gates/ci-attempts.json) يربط كل مصدر وتشغيل وفشل بإصلاحه، ويحفظ بصمة السجل الأصلي ومقتطفاته.

| البوابة | الحالة الحالية | المطلوب التالي |
|---|---|---|
| حالات symlink الأربع | PASS على Linux بالمصدر والتشغيل المحددين أعلاه | لا إعادة ما لم يتغير المتأثر |
| CI الكامل | غير مقبول بعد؛ المصدر المصحح في طابور GitHub | قراءة نتيجة التشغيل القائم ومعالجة فشله المحدد إن وجد |
| استرجاع حزم الإصدار | مبرمج؛ لم ينفذ | نجاح مهمة retrieval مع إيصال البصمات الفعلي |
| هدف Linux | مجهز للمراجعة؛ لم يُبن أو يُختبر فعليًا بعد | native image proof، ثم API/DB/readiness/drain على بيئة الاختبار المعتمدة |
| إعداد الإصدار والترقية | محجوب | الأدلة والتوقيعات والإعدادات المطلوبة في عقد الإصدار؛ لا تجاوز لها |

R05 تبقى مغلقة محليًا فقط. R06 يبقى نطاقها الأساسي مكتملًا مع الاستثناءات الموثقة وقبولها الشامل مفتوحًا. R07 تبقى مكتملة التشخيص المحلي الأساسي على `4c7b01c`، مع `formalR07Acceptance=false` و`productionAcceptance=false`؛ لا C2 أو ترقية أو نشر مستنتج من هذه الدفعة.
