# R05 native laboratory and decisions — 2026-10-17

Status: IN_PROGRESS; no technical-owner approval recorded. This document is a recommendation, not an approval or closure certificate. R06 and R07 remain gated; existing R07 evidence is preserved on its separate branch.

## Scope and evidence

The project owner explicitly authorized a new, isolated PostgreSQL 16 cluster with synthetic data, including a native Windows fallback when Docker/WSL is unavailable. No existing database, Neon endpoint, production data, service installation, historical migration, Binding or Consent may be modified by this preparation.

The implementation adds an explicit native creator rather than disguising a native server as Docker. It creates a fresh random private directory, removes inherited directory access before storing credentials, initializes SCRAM authentication, binds only 127.0.0.1 on a newly selected port, and creates two databases and restricted migration roles. Official target preflight must confirm PostgreSQL major version, system identifier, database OID, nonce marker, role privileges and empty schemas. Backup retains that preflight and additionally checks the recorded data directory, postmaster PID/port and postgres binary hash. DB-V must still be empty before restore; restore retains the existing strict TOC filter, single transaction, no-owner/no-ACL options, full catalog/content comparison and unchanged-source check.

Three new policy tests exercise changed source/version/PID/port/binary, remote targets and privileged roles. Unit checks are not a substitute for actual cluster/backup/restore evidence. Native Windows uses locale C and UTF8, a declared difference from the Docker baseline, to be recorded in runtime evidence. PostgreSQL 17 binaries found elsewhere are not used.
