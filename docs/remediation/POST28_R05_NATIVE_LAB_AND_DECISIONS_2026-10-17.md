It creates a fresh random private directory, removes inherited directory access before storing credentials, initializes SCRAM authentication, binds only 127.0.0.1 on a newly selected port, and creates two databases and restricted migration roles. Official target preflight must confirm PostgreSQL major version, system identifier, database OID, nonce marker, role privileges and empty schemas. Backup retains that preflight and additionally checks the recorded data directory, postmaster PID/port and postgres binary hash. DB-V must still be empty before restore; restore retains the existing strict TOC filter, single transaction, no-owner/no-ACL options, full catalog/content comparison and unchanged-source check.

Three new policy tests exercise changed source/version/PID/port/binary, remote targets and privileged roles. Unit checks are not a substitute for actual cluster/backup/restore evidence. Native Windows uses locale C and UTF8, a declared difference from the Docker baseline, to be recorded in runtime evidence. PostgreSQL 17 binaries found elsewhere are not used.

## Preservation and approval gates

Audit implementation detail: `PrismaAuditRecordRepository.ts:138–184` already supplies create-only `save`, transactional `saveInTransaction`, sanitization and explicit `AUDIT_APPEND_ONLY_DUPLICATE` refusal. `ManageAuditRecordsUseCase` makes the administrative surface query-only. Therefore the preferred journal implementation is new, scoped Audit records through this existing boundary, with stable operation/phase references and explicit duplicate reconciliation, rather than a new journal table. This is repository-level append behavior, not proof of a universal database UPDATE/DELETE prohibition. The existing integrity API explicitly sets `cryptographicVerification:false`; its chain references must not be represented as cryptographic signatures. The historical audit retention INSERT envelope in migration `20261012010000_audit_workspace` applies classification and approved policy; do not bypass it or equate audit retention with the PDF's 180-day retention. Assets save does not currently expose the same atomic audit context, so an atomic completion record needs reviewed transaction wiring; storage/lifecycle phases also need recoverable PREPARED/COMPLETED/FAILED evidence. Any new audit rows and Asset rows are explicit remediation deltas requiring comparison review, not permission to weaken baseline invariants or change old audit evidence. These are concrete Audit-owner acceptance questions before implementation/execution of remediation, while the absent published Asset integration contract provides no source basis to require a new Outbox event today.

Capture and compare exact pre/post Binding, Consent decisions, tracker version, attestation and historical rows, including timestamps. Never call Student allocate, bindDocument or consent(true) to repair the old reference. Existing historical synthetic ACTIVE fixtures prove preservation only, not trustworthy content or review eligibility.

A mock provider, no-op sanitizer or synthetic attestation cannot satisfy those gates. Preserve negative review cases for revoked/expired/future consent, foreign owner, stale owner version and expired asset without creating new consent.
