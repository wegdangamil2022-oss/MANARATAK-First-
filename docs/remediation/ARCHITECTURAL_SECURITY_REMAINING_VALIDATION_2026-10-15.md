# ما بقي للتحقق بعد مراجعة الخطة والمصدر

المرجع: [مراجعة ما بعد الدمج](../reviews/POST_CLOSURE_PLAN_SOURCE_REVIEW_2026-10-15.md)، [تسليم التشغيل](ARCHITECTURAL_SECURITY_RUNTIME_HANDOFF_2026-10-15.md)، وسجلا section27/28. هذه قائمة عمل لاحق، ولم تُشغل أوامرها الثقيلة أو قواعدها أو مزودوها في جولة المصدر.

## 1. مصدر محدود لم يُعد فحصه

| المطلوب | ما الذي ما زال غير مثبت | السبب |
| --- | --- | --- |
| حالتا HTTP من B13CommandBoundary | status 400 عند غياب إصدار capture أو مفتاح الطلب بعد الإصلاح؛ المخرجات القديمة 22 PASS و2 FAIL | المستخدم طلب إصلاح خطأين أو أقل دون إعادة؛ بقيت النتيجة التاريخية كما هي |
| فحوص الائتمان الأصلية | replay بعد ائتمان كامل، تغيير نية، حدود مبلغ/عملة/إصدار في المسار الأصلي الكامل | فحص V8 فقد binding لـInvoiceStatus؛ 3 نتائج مؤكدة و2 خطأ تجهيز و4 نتائج غير متحققة، ولم يُعد |
| مجموعات المالية/الخريجين المتأثرة ببدائل الاختبار | تشغيل الحالات القديمة بعد تزويد FinanceCommandRecord ومدخل expectedVersion وتحديث صيغة trim | تم تحديث الاختبارات، لكن لم تُعد المجموعة السابقة أو suite شاملة |

انتهى فحص أنواع واحد ناجح للمصدر الحالي. الاختبارات الجديدة الخاصة بتصحيحات المتابعة 10/10 ناجحة. لا تُجمع نجاحاتها لإخفاء الحالات الأصلية غير المعادة. مخرجات الفواحص السبعة محفوظة من B14، ولا تُدعى إعادة حديثة لها.

## 2. قاعدة PostgreSQL معزولة

يلزم inventory/checksum/schema للهدف غير التشغيلي، ومراجعة migrations الجديدة/الأيتام والتوافق قبل التطبيق. ثم إثبات CAS/locks وSerializable وRepeatableRead، التنافس على نفس الطلب/الموافقة/الحجز، rollback عند فشل audit/outbox/receipt، التراجع والاستعادة، وقيود FK/ربط الأصول/purge. يحتاج شرط whitespace الجديد تجربة SQL فعلية مع TAB/NBSP/BOM، وتحتاج الموافقة/السحب بيانات قديمة ممثلة. بدائل الذاكرة لا تثبت هذه الخواص.

## 3. متصفح → API → DB في بيئة اختبار

جلسات بأدوار حقيقية للتأليف/المراجعة/النشر/السحب وعزل المسودات، تبديل AR/EN والصفحات وروابط المعرفات، الجلسة/CSRF/refresh/revoke، سحب موافقة الخريج، واستعراض وتنفيذ المالية وفق maker/checker وموافقة صاحب المحفظة. لا تُستخدم بيانات تشغيلية أو دفع/بريد حقيقي لهذه السلسلة.

## 4. العمال والمزودون المعزولون

عاملان يتنافسان على lease، reclaim/retry/DLQ وSIGTERM/drain، freshness مشتركة في Redis، وidempotency/abort. للمزود المالي: sandbox أو بديل معتمد، webhook موقّع/replay وفشل/انقطاع/unknown outcome وتسوية؛ وللبريد مزود اختبار غير مرسل حقيقي. لا يصدر هذا المستند موافقة تشغيل أو تفعيلًا لأي مزود.

## 5. الإصدار والجاهزية

قبول على **Node 22** المعلن، وأدلة CI/artifact/signing/three-unit routing ومراجعة التشغيل وفق section27 وsection28. build/E2E وصورة التشغيل والتجارب الأوسع تبقى خارج طلب المصدر الخفيف الحالي. section27 غير مغلق كليًا وsection28 `NO_GO`، فلا إعلان production ready قبل أدلتهما الفعلية.

## قرارات نطاق باقية وليست أخطاء كود معلقة

حجز جلسات الإرشاد خارج الإصدار بقرار موثق؛ يحتاج سياسة منتج عند إعادته مستقبلًا. محتوى الترجمة ما زال `INFRASTRUCTURE_ONLY` وتفعيله يحتاج بوابته التشغيلية. الخطة تنتهي B14 ولا تعرّف B15. الخطوة العملية التالية بعد المصدر هي تجهيز **بيئة DB ومتصفح ومزود اختبار معزولة** بالأدوار والبيانات المناسبة، ثم تنفيذ ما سبق ضمن تفويض تشغيل منفصل؛ لم تُجهز أو تُشغل تلقائيًا هنا.
