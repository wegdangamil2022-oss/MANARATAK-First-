# ربط القالب المعتمد بحساب الطالب

الحالة: تنفيذ المصدر والقالب القابل للتحرير مكتملان في الفرع `codex/section-13-certificates`. **التفعيل الحقيقي في جوجل استوديو غير مثبت**؛ المستخدم أوضح أن بيئة التشغيل المطلوبة غير متاحة هنا، ولم تُزوَّد هذه الجلسة بقاعدة بيانات أو تخزين أو مزود توقيع.

## السلوك

- التصميم `manaratak-completion-2026-10-10-v1` هو الخيار الافتراضي للقوالب الجديدة ومسودة MNR-SIGNATURE. يمكن ترقية قالب سابق بإنشاء نسخة جديدة من الإدارة، دون تغيير شهاداته التاريخية. الخيار ثنائي اللغة وأفقي، ويحفظ الشعار الرسمي دون عبارة «للفرص التعليمية».
- المشهد المتجهي مشترك بين معاينة الإدارة وSVG وPDF. رقم الشهادة والتاريخ وQR تأتي من سجل الإصدار. تضمين الخطوط يحافظ على العربية، وPDF يستخدم glyph paths تفاديًا لخلل إعادة ترتيب الأحرف في تحويل SVG. توقيع الخط ليس توقيعًا تشفيريًا؛ لا يُولَّد خط يدوي مزيف عند غياب أصل توقيع معتمد.
- الإتمام المؤهل فقط يمر عبر worker/outbox إلى إصدار واحد ثم توليد PDF/preview/QR وربطها بنفس certificateId. ما زالت الأقفال والمعاملات وإعادة المحاولة/المصالحة والحماية السابقة قائمة.
- حساب الطالب يقرأ endpoint الشهادات الخاص بالمالك مباشرة، ويحدّث القائمة كل خمس ثوانٍ عند ظهور القسم، حتى إذا كانت فارغة أولًا. يمكن معاينة الشهادة وتنزيل PDF عبر grants خاصة قصيرة العمر، مع فحص MIME وتنظيف object URLs. «عرض المزيد» يستخدم cursor دون قطع القائمة عند أول 50. التحديث اليدوي يرجع للصفحة الأولى؛ تحميل صفحات إضافية يوقف polling حتى لا يحذف ما حمّله الطالب.
- القراءة من dashboard تظل عبر بوابة مالك الشهادات؛ عدم ظهور نسخة cached من dashboard لا يمنع قائمة الشهادات المباشرة. تعرض الواجهة أخطاء القراءة والتجهيز بدل الادعاء بوجود ملف قابل للتنزيل.
- يمكن تثبيت أسماء الإنجاز العربية/الإنجليزية من محتوى الدورة التاريخي داخل الظرف الموقّع. لا توجد ترجمة أو transliteration تلقائية لاسم الطالب.

## التحقق

نتائج التحقق المحلي النهائية:

- اختبارات الشهادات: 170 اختبارًا ناجحًا في 21 ملفًا؛ أُعيدت الاختبارات الخمسة الجديدة بعد التصدير النهائي ونجحت.
- `npx tsc -b apps/api apps/admin apps/web`: ناجح.
- بناء الإنتاج لواجهتي `@manaratak/admin` و`@manaratak/web`: ناجح؛ بقيت تحذيرات حجم الحزم وتحذيرات مسارات Cairo الموجودة مسبقًا في الإدارة.
- `certificates:source:closure`: ناجح، 94/94. حُدّثت فحوص العنوان والموقّع لتقرأ القالب المعتمد، وفحص التاريخ ليتتبع لغة المستخدم الحالية.
- فحص جودة المصدر وتغطية التدقيق الأمني للشهادات: ناجحان. ESLint للملفات المعدلة: صفر أخطاء، سبعة تحذيرات في صفحة الإدارة السابقة.
- اختبار المتصفح: PASS، ظهور إصدار بعد قائمة فارغة، معاينة، تنزيل PDF، pagination؛ صفر أخطاء console. واجهات API بديلة و`liveDatabase: false`.
- تصدير SVG/PDF من المصدر النهائي: ناجح، دون قاعدة بيانات. `git diff --check`: ناجح.

اختبار CertificateStudentAccountFlow يستعمل مسار الإصدار والتوقيع التطويري والتوليد والقارئ وStudentWorkspaceRouter وبوابة dashboard الحقيقيين؛ persistence وcustody والتسليم الخارجي بدائل اختبار. يثبت الإصدار الواحد، الهوية التاريخية، عرض الطالب المالك، التنزيل الخاص، التحقق العام، رفض طالب آخر ورفض التنزيل بعد الإلغاء. لا يثبت أقفال PostgreSQL أو HSM.

اختبار المتصفح `scripts/certificates/verify-student-browser.mjs` يحمل المكونات الحقيقية وApiClient، ويحاكي API فقط: قائمة فارغة ثم ظهور إصدار في polling، grant مع idempotency key، عرض SVG، تنزيل PDF صالح، وتحميل الصفحة التالية. يستعمل بيانات PREVIEW؛ لا يدخل حساب طالب حقيقيًا ولا يكتب إلى DB.

## تجهيز جوجل استوديو

1. تشغيل API المتصل بقاعدة PostgreSQL في بيئة المشروع وإكمال مسار الترحيلات المعتمد، بما فيه ترحيل issuer pending السابق وترحيلات التعلم. لا تشغّل migrate/seed/backfill على قاعدة غير محددة لمجرد فتح المعاينة.
2. تزويد EAP بمخزن ورفع/تفعيل/منح تنزيل خاص يعملان؛ مراجعة روابط الملفات القديمة العامة. تضمين مجلد `packages/infrastructure/assets/certificates` مع التطبيق، وأصول `/admin/fonts/` و`/admin/brand/` مع الإدارة.
3. لبيئة إنتاجية يجب حقن `certificateSignatureService` من KMS/HSM معتمد، وتوفير reference مع مفاتيح لا تُصدّر. `certificateSignatureService: asValue(null)` ما زال عدم تزويد مقصودًا، ويمنع الإنتاج من الإصدار. **HMAC أو signingSecret للتطوير لا يحلان مكانه**. توفير مزود فعلي يستلزم تكييف عقد التوقيع الحالي مع مزود البيئة؛ لم يتم اختراع موصل أو مفاتيح غير موجودة.
4. ضبط `CERTIFICATE_PUBLIC_VERIFICATION_BASE_URL` على أصل HTTPS الحقيقي للواجهة، و`CERTIFICATE_SIGNING_KEY_REFERENCE` على مرجع الجهة المعتمد. لا تستخدم example.org أو روابط المعاينة في إصدار حقيقي.
5. تفعيل الجهة والقالب بصلاحيات IAM الصحيحة، ثم `CERTIFICATE_COMPLETION_WORKER_ENABLED=true` ومدة polling المناسبة. اختيار التصميم على النسخة الجديدة لا ينشط الجهة أو القالب تلقائيًا.
6. قبول runtime بحساب طالب تجريبي: الالتحاق بدورة native مؤهلة، إتمام نسخة المنهج المثبتة، ملاحظة حدث الإتمام والدفتر/outbox، انتظار ربط الملفات، فتح «إنجازاتي وشهاداتي»، معاينة وتنزيل PDF وفتح QR، ثم اختبار ملكية حساب آخر والإلغاء. اختبر restart/failure/replay على مخزن/DB قابلين للرمي قبل الإنتاج.

لم تُطبَّق ترحيلات، ولم تُغيَّر بيانات حقيقية أو ACL، ولم يُنشَر التطبيق أو يُدمج main في هذه الجولة. هذا التقرير لا يعلن إغلاق التشغيل أو زوال متطلبات KMS/EAP/PostgreSQL الواردة في التقرير السابق.
