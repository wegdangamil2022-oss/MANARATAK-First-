# R09 — مسار الطالب والعودة إلى الدرس

الحالة `IN_PROGRESS_LEARNER_AND_CMS_BROWSER_VERIFIED`. مصدر التنفيذ الأول `c659a89ce199ee7857b3df52f11a780d30f7c9d4`، وتصحيح محاكاة المتصفح `a7455c75e51f3c5a332b3577501a04b48725bf9c`. أُضيف إصلاح إذن المختبر وتعقيم CMS في `7b265fc63f4e42f30560f64ce01a9f575ccf6a33`، ثم تحديث مرجع جرد البيئة في المرشح `ce0690c36759fc73ac202a679f905054b7a4607b`. هذا سجل دفعة محددة، وليس قبول R09 الشامل أو إذنًا بالنشر. حالة R08 العملية وحالات R05/R06/R07 السابقة محفوظة.

## الإصلاحات

- أصبحت وجهات العودة المسموحة تشمل `/ar/student/...` و`/en/student/...`؛ كان حارس ما بعد الدخول يرفضها ويعيد الطالب إلى البداية. بقي التحقق من origin ومنع وجهات الإدارة والروابط الخارجية.
- أصبح رابط عودة الدرس يحتفظ بالمسار والاستعلام و`#fragment` معًا؛ كان fragment يُسقط عند الانتقال إلى تسجيل الدخول.
- أصبح رفض مساحة دورة لعدم التسجيل يعيد `403 COURSE_ENROLLMENT_REQUIRED` بعقد problem details. كان الخطأ العادي يصل إلى المعالج العام فيتحول إلى 500 عام، فلا تظهر واجهة التسجيل. لم تتغير حراس المصادقة أو صلاحيات الطالب؛ الأخطاء غير المعروفة تستمر إلى المعالج العام دون كشف تفاصيلها.
- كشف CI أن محاكاة `useLocation` في B03 لا تتضمن `hash`، فأصبح الرابط في الاختبار يحتوي النص `undefined`. أُكملت المحاكاة بحقول المتصفح الفعلية وأصبح assertion يثبت query وfragment؛ لم يُضعف الشرط ولم يتغير التنفيذ لإرضاء محاكاة ناقصة.

## الفحوص المستهدفة

[الأدلة الخام ونطاق كل تشغيل](../reviews/evidence/post28/a7455c75e51f3c5a332b3577501a04b48725bf9c/r09-targeted-source/evidence-index.json): فشل اختبار وجهة العودة قبل الإصلاح، ثم نجحت ثلاث حالات مباشرة التأثر مع إبقاء الحالات غير المختارة منفصلة. وفشل عقد عدم التسجيل قبل التصحيح، ثم نجح اختباراه: الرفض المعروف 403 وترك الخطأ غير المعروف للمعالج العام. نجح اختبار B03 المتأثر بعد اكتمال محاكاة الموقع؛ لم تُعد مجموعته كاملة يدويًا.

نجح فحص أنواع API/Web وفحص تركيب أدوات التشغيل في دفعة التنفيذ؛ لا بناء كامل محلي متكرر. يتولى CI بواباته الإلزامية عند دفع المصدر، ولم تُحذف بوابة أو assertion. التشغيل `39341546589` على `c659a89` فشل في اختبار B03 المذكور، فتُخطي بناء الحزم وتشغيل المتصفح بسبب التبعية؛ لا يُحسب دليل متصفح ناجحًا.

## نطاق تجربة المتصفح

التشغيل `39343384826` على `a7455c7` اجتاز فحوص المصدر الرئيسية واسترجاع الحزم وبناء صورة Linux x64 / Node 22. نجحت readiness للوحدات الثلاث على SHA واحد، ثم العودة للرابط العربي مع query وfragment بعد دخول حقيقي، ورفض مساحة الدورة 403 قبل التسجيل، ثم التسجيل 201 وقراءة مساحة الدرس 200. فشل تحديث الدرس 500 لأن إعداد مختبر DB-T لا يمنح كتابة `CourseLessonProgress`. لم يُثبت هذا التشغيل تقدمًا محفوظًا أو عزل الطالب الثاني. [الفشل الخام وسجل API والتنظيف](../reviews/evidence/post28/a7455c75e51f3c5a332b3577501a04b48725bf9c/r09-learner-failed-runtime/evidence-index.json) محفوظة؛ خرجت API بالرمز صفر وأُزيلت القاعدة والشبكة والحاوية المملوكة، دون لمس قواعد سابقة.

الإصلاح يضيف العلم الصريح `--r09-learner-fixtures` إلى تهيئة قاعدة جديدة محروسة فقط، ويمنح `INSERT/UPDATE` على جدول تقدم الدرس وحده. لا يوسع قائمة الجداول الافتراضية ولا يمنح DELETE أو DDL أو كتابة سجل migrations. يثبت التشغيل اللاحق الامتيازات الفعلية قبل بدء المتصفح، مع إبقاء جميع اختبارات HTTP وDB كما هي. هذا تصحيح إعداد المختبر؛ لا نُسقطه تلقائيًا على أذونات إنتاج غير مفحوصة.

نجح [التشغيل البديل 39344907974](https://github.com/wegdangamil2022-oss/MANARATAK-First-/actions/runs/39344907974) على `ce0690c`: بدأ الطالب من رابط عربي مباشر، وسجل دخوله وسجل في الدورة وأكمل درسًا واحدًا من اثنين، وبقي التقدم 50 بعد إعادة تحميل الصفحة مع بقاء fragment. أثبتت قراءة DB درسًا مكتملًا وسجلَّي Audit وسجلَّي Outbox للالتحاق والتقدم. رُفض API الإدارة 403 وأعادت واجهتها الطالب لمساحته. رُفض حساب ثانٍ مستقل قبل التسجيل دون محتوى درس، ثم بقي تقدمه صفرًا بعد التسجيل وتقدم الأول 50. امتيازات جدول الدرس الفعلية INSERT/UPDATE=true وDELETE=false، ودور `post28_app` دون DDL أو كتابة ledger أو أي أعلام إدارية. [الدليل الخام والصورة وبصمة الأرشيف](../reviews/evidence/post28/ce0690c36759fc73ac202a679f905054b7a4607b/r09-learner-runtime/evidence-index.json).

نجحت جميع check runs الثلاثة والعشرين، بما فيها نتيجة CodeQL المنفصلة؛ لا فحص فاشل أو معلق. [إيصال GitHub والتتبع الجزئي](../reviews/evidence/post28/ce0690c36759fc73ac202a679f905054b7a4607b/r09-handoff/evidence-index.json) محفوظان. حقل combined status القديم يعيد `pending` مع قائمة statuses فارغة؛ الحكم هنا من check runs الفعلية المكتملة، لا من ذلك الحقل القديم.

لم يظهر page error أو استجابة 5xx في مسار الطالب. رسائل console السلبية 401/403 ومحاولات صور Unsplash المحجوبة متوقعة ومحفوظة؛ لا ندعي أن console خالٍ منها. استُخدم HTTPS مع فحص اسم المضيف وتثبيت SPKI للشهادة المحددة و`ignoreHTTPSErrors=false`. خرجت API بالرمز صفر وأُزيلت الحاوية وPostgreSQL والشبكة المملوكة. لم يتصل التشغيل بـNeon أو إنتاج أو مزود مؤثر. عمال الخلفية معطلون في هذا المختبر؛ إثبات Outbox لا يساوي إثبات معالجة المستهلكين.

## تعقيم نصوص CMS

أشار check CodeQL `118371706902` إلى إدخال HTML غير معقم في `DOMParser` داخل `CmsRichText`، وهو التنبيه التاريخي 89 الذي ظهر بوصفه جديدًا على فرق PR الحالي. كانت هناك قائمة سماح وإعادة بناء بعناصر React، لكن لا نعتمد عليها لإخفاء تنبيه مرحلة التحليل. استُبدل التحليل الخام بـ`DOMPurify` المثبت بإصدار `3.4.17` في lockfile، مع قائمة tags/attributes ضيقة و`RETURN_DOM_FRAGMENT` ثم إعادة بناء عناصر React القائمة؛ يبقى شرط الروابط HTTPS بلا بيانات دخول و`noopener noreferrer`. لا إعادة حقن لسلسلة HTML، ولا استثناء CodeQL أو تصنيف false positive. [واجهة المكتبة الرسمية وحدود تعديل الناتج](https://github.com/cure53/DOMPurify#readme).

استُبدل أيضًا شرط regex السابق بفحصي `includes` خطيين؛ لا نُبقي تعبيرًا متكرر المسح للبحث عن بداية HTML. نجحت أربعة فحوص مكون فعلية في متصفح Edge/Chromium محلي: بقاء التنسيق والرابط المسموح، إزالة الشيفرة والأحداث والروابط غير المسموحة، حمولة HTML متداخلة مشوهة، وبقاء نص المقارنة العادي. لم تُنفذ شيفرة الحمولة ولم يُطلب مورد خارجي ولم يظهر page error. [هذا التشغيل ونطاقه](../reviews/evidence/post28/7b265fc63f4e42f30560f64ce01a9f575ccf6a33/r09-cms-local-component/evidence-index.json) على شجرة العمل التي حُفظت لاحقًا في `7b265fc`، وليس ادعاء أنه تشغيل كامل من حزمة إصدار نظيفة. أُضيف نفس الفحص إلى مهمة Linux بعد تجربة الطالب، لإثباته على المرشح المحدد أيضًا.

نجح الفحص نفسه بأربع حالاته أيضًا على Chromium/Linux في CI على `ce0690c`، دون page errors أو طلبات خارجية؛ إيصال `cms-rich-text-proof.json` ضمن دليل التشغيل أعلاه. نجحت فحوص الأنواع للواجهتين المتأثرتين وعقد أمر CI الموجه. مرجع `NODE_ENV` الجديد في أداة المكون استلزم تحديث جرد البيئة؛ دُفع ذلك في `ce0690c` وثبتت البوابات عليه، مع بقاء 320 اسمًا دون قراءة قيم أسرار. لا يُحسب التشغيل السابق `7b265fc`، الذي سبق تحديث الجرد، نجاحًا للبوابة.
