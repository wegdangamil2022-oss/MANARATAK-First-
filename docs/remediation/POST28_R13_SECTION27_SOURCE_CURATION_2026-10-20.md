# R13 — ربط مهام القسم27 ومعالجة فشل CI

**اكتمل ربط المهام38 بمتطلباتها وملفات التنفيذ والفحوص المرتبطة. هذا فهرس مراجعة مصدرية، وليس إغلاق القسم27 أو قبول R13.** لا تُحسب نتائج اختبارات جديدة لمجرد وجود ملفاتها، ولا يُعاد وسم الأدلة القديمة باسم مرشح جديد.

مصدر الربط `68bb1809698435416656cb7b51ed0c1f5f1a545a`. تطابقت معرفات XMI-001…XMI-037 وXMI-FG-038 بين التقرير الأصلي وسجل القسم27 وفهرس الإصدار. رُبطت إلى60 ملف تنفيذ مختلفًا، مع بصمة Git blob وخطوط ربط رموز/دوال حيث توفرت، وملفات الفحص التي تشير إلى الرمز أو معرف المهمة. روابط الفحص مرشحة للمراجعة وليست إثبات تغطية كاملة أو نجاح.

لكل مهمة حُفظ نص المتطلب الأصلي، موقعه، الحالة والحدود التاريخية، ملفات التنفيذ وبصماتها، ملفات الفحص المرتبطة، وكون هذه الفحوص لم تُعد في هذه الدفعة. بقيت35 مهمة بحالة «مراجع التنفيذ والفحص محددة؛ المراجعة باقية»، وثلاث مهام عليها ملاحظات مراجعة مصدرية مركزة؛ لا نسبة إنجاز تقديرية أو توقيع مستقل مختلق.

## إصلاح CI الفعلي

فشل push CI رقم39491660827 عند `68bb180` في خطوة **Cross-cutting source preflight** برسالة `Environment inventory stale`. نجحت وظائف الترجمة وإعداد النشر وR08 المستقل، وتُخطيت وظائف استرجاع الحزم وLinux المعتمدة على المصدر بسبب الفشل؛ لا تُعرض كناجحة أو منفذة.

السبب أن اختبار `tests/release/r13-evidence-cli.test.mjs` المضاف في الدفعة السابقة يذكر `env.SOURCE_SHA`، بينما لم يُحدَّث رابط المصدر في `ENVIRONMENT_INVENTORY.md`. أعدت توليد الفهرس بالأداة القائمة: تصحيح سبب الفشل هو إضافة رابط الاختبار إلى صف SOURCE_SHA. وبعد إضافة اختبار مدخل الترقية أدناه، أُضيف رابطه إلى صف PATH القائم أيضًا. بقيت324 اسم متغير كما هي؛ لم تتغير قيم أو أسرار أو `.env.runtime.example` أو validator أو خطوة CI.

نجح `environment-inventory.mjs --check` بعد التصحيح، ثم أُعيد فقط بعد إضافة مرجع الاختبار الجديد إلى المصادر المتتبعة ونجح. هذا فحص متأثر مباشرة؛ لم تُعد بقية preflight الناجحة أو مجموعات R06–R12 أو build المشروع. لم يُعد اختبار فاحص الأدلة البرمجي الذي لم يتغير في هذه الدفعة. نتيجة CI للتصحيح تُتابع بعد الرفع، ولا يحمل التصحيح نتيجة تشغيل سابق.

## مدخل الترقية على Windows

رُصدت أثناء القراءة مقارنة Windows القديمة نفسها في `promote-environment.mjs`: مسار URL لا يطابق مسار argv الأصلي، فيمكن أن ينتهي الأمر دون تنفيذ وظيفته. أُصلحت بدالة اختيار مدخل صغيرة تستخدم المسار المطلق وfile URL. اختُبرت الدالة مباشرة مع المسار الصحيح ومسار اختبار آخر وغياب المدخل، واختُبر أن استيراد الوحدة لا يشغل CLI. فشل اختبار الدالة قبل الإصلاح ثم نجح الاختباران بعده.

نجح أيضًا اختبارا reconciliation القائمان الأكثر اتصالًا بالتعديل: accepted يُستعلم حتى terminal، وaccepted المستمر ينتهي بمهلة ولا ينتج healthy. يستخدمان fetcher صناعيًا؛ لم يُشغّل أمر promotion أو dry-run، ولم تُستدعَ خدمة تحكم فعلية. بقيت `RELEASE_PROMOTION_ALLOWED` والتحقق من الأدلة الموقعة والبيئة وGO وapprovedEnvironments قبل reconcile كما هي. هذا إصلاح مدخل، وليس تفويض نشر.

## الحالة ونقطة الاستئناف

- `sectionClosed=false` و`runtimeVerified=false` التاريخيان محفوظان. ملف الفهرس الجديد منفصل حتى لا يمحو الحالات والأدلة الأصلية.
- `R13-B01` ليس محلولًا بالكامل؛ صار له فهرس محدد بدل أسماء رموز عامة. يبدأ الاستكمال بالمراجعة المتبقية لمهام العلاقات/الدورات وXMI-033، ثم قبول مصدر حقيقي قبل تجميد C2.
- أُصلح مدخل promotion وفُحص معزولًا كما سبق؛ لا قبول لتشغيل نشر أو reconciliation حقيقي، ولا إزالة لأي بوابة.
- عوائق R13-B02…B06 واستثناءات R11/R12 باقية. لا validation أو staging أو إنتاج أو Neon أو قاعدة بيانات أو مزود خارجي في هذه الدفعة.
