# R06 — إغلاق النطاق الأساسي

**R06 — اكتمل النطاق الأساسي المتفق عليه، مع استثناءات موثقة؛ القبول الرسمي الشامل ما زال معلقًا.**

المصدر المنفذ `d1770592c2ec171b14b6e755b3e138dfa2beed4a`، التشغيل `ba99d4f2-2e14-40de-bb68-b5f726089e7e`، فرع `feat/post28-r07-artifact-preparation`. الإغلاق يخص التشغيل المحلي الأساسي المدعوم وميزات القراءة والهوية المحمية؛ لا يشمل تشغيل الدفع الخارجي أو العمال الآليين أو اعتماد كتابة الإدارة الحساسة. لا ادعاء26/26 أو نسبة إنجاز تقديرية.

## المتبقي الحرج الذي أُنجز

كانت E01 فجوة سلامة فعلية: الفهرس المركب العادي يسمح بتكرار هوية قبول تحتوي NULL عند الكتابة المباشرة. بقيت مسارات الإدارة والاستيراد محمية بأقفالها، لكنها لم تكن بديلًا لقيد قاعدة البيانات.

أُدرج الترحيل الجديد `20261019000100_admission_null_identity` بعد [مراجعة ترقية محددة](POST28_R06_NULL_IDENTITY_ROLLOUT_REVIEW_2026-10-19.md). يحافظ على الأعمدة الأربعة واسم الفهرس ودلالة الهوية عبر الحالات كلها، ويضيف NULLS NOT DISTINCT. يمنع قفل الجدول السباق بين تدقيق التكرارات واستبدال الفهرس، بمهل5ثوان للقفل و60ثانية للاستعلام. التكرارات القائمة توقف الترحيل دون حذف أو تسوية تلقائية. تصادم FK SET NULL يرفض الحذف ويحفظ المصدر والتابعين؛ لا حذف صامت للمتطلبات.

حارس الانتقال يقبل هذه الإضافة وحدها ببصمتها المحددة، مع تطابق110 ترحيلات تاريخية ومخطط Prisma القديم والتحقق من أدلة إغلاق R05. لم تُعدل أدلة قبول R04/R05 أو أي ترحيل تاريخي. أُصلح أيضًا حارس فرع تجهيز R06 ليدعم فرع التجميع الحالي، وأصبح التجهيز يفحص خاصية الفهرس الإضافية مباشرة؛ تطابق Prisma وحده لا يكفي لإثباتها.

## أدلة التشغيل الفعلية الجديدة

- مختبر PostgreSQL16.15 جديد، بهوية خادم وقاعدتي U/V مستقلتين وأدوار ترحيل وتطبيق محدودة. استعيد أرشيف صناعي موثق من عمل R05 دون تشغيله على القواعد القديمة.
- تحقق سجل110 السابق كاملًا، وكان تدقيق مجموعات الهوية المكررة صفرًا. أُخذ خط أساس كامل قبل111، ونسخة احتياطية استعيدت إلى V الفارغة؛ تطابقت محتويات الجداول الـ282 وتعريفات القاعدة، وبقي المصدر دون تغيير.
- نفذ **Prisma migrate deploy** الترحيل111، وأُثبت سجل111 بالأسماء والبصمات والحالات المكتملة. المقارن الصارم حافظ على **281 نموذجًا و8 ثوابت والمجاميع المالية الدقيقة**؛ جميع بصمات جداول التطبيق مطابقة قبل الترحيل وبعده، والتدقيقات التسعة صفر.
- ثبت الفهرس الفعلي: unique/valid/ready وNULLS NOT DISTINCT، بنفس الأعمدة والاسم دون predicate أو تعبيرات. نجح Prisma schema diff وmigrate status، ثم أعيد deploy دون تغير بيانات أو تعريفات أو سجل.
- كاتبان مستقلان بدور التطبيق حاولا إدخال نفس هوية NULL مباشرة: صف واحد فقط التزم والآخر رُفض P2002. فشل إدخال مكرر داخل معاملة تضم تعديل الجامعة أعاد المعاملة كلها؛ بقيت الجامعة كما كانت. دور التطبيق بلا superuser أو CREATE أو قراءة سجل الترحيلات.
- أُوقف المختبر النهائي إيقافًا سليمًا بعد فحص PID والملف التنفيذي. لم تحذف قاعدة ولم تلمس مجموعة أخرى.

المحاولة الأولى انقطعت أثناء استعادة قاعدة التحقق قبل استدعاء111؛ احتُفظ بسجل الفشل ولم تُستخدم الاستعادة الجزئية أو تُحذف لإظهار نجاح. نجحت التجربة النهائية في مختبر جديد مع عملية أب مستمرة من الإنشاء حتى الإيقاف. سبب انقطاع العملية الأولى غير محسوم؛ لا يُعرض كاختبار ناجح أو كفشل للترحيل111.

## الفحوص المستخدمة وحدود إعادة التشغيل

نجحت6 فحوص جديدة لحارس الانتقال: القبول المحدد ورفض تغيير تاريخ/بصمة/اسم/مخطط أو ترحيل زائد، ومعها36 فحصًا متأثرًا لحراس تجهيز المختبر والصلاحيات. نجح فحص حدود التخزين وملكية281 نموذجًا، وجودة المصدر وفحص صياغة تجهيز R06. لم تُعد مجموعات الانحدار العامة أو البناء أو فحوص PDF.

أدلة [مرشح التشغيل السابق](../reviews/evidence/post28/a8210404f63e2408fc911be74ff91bf8bc47aa8e/R07-owner-priority-browser/evidence-index.json) تثبت API/Web/Admin من الحزم الفعلية ومسار المتصفح الأساسي: دخول الطالب، حسابه، رفض الحساب الأجنبي والخروج؛8 ملاحظات و85 استجابة دون أخطاء صفحة أو خادم. بقي مصدرها الأصلي واضحًا؛ لم نعد بناء الواجهات أو نسب هذا التشغيل إلى SHA الجديد لأن شيفرة التطبيق واعتماداته لم تتغير في إصلاح SQL وأدوات التحقق هذا.

أُعيد فقط ما تأثر: إثبات إدراج111 في سجل Prisma والفهرس الفعلي وحفظ الصفوف والنسخ والتزامن وrollback وإعادة التطبيق. إثباتات المرشح السابقة لأربع حالات NULL والتحديث وFK وفشل DDL بعد DROP محفوظة في [تقرير الإصلاح السابق](POST28_R06_NULL_IDENTITY_REPAIR_2026-10-19.md)، ولم تُضعف اختبارات تاريخية تُنشئ تكرارات قبل الإصلاح. تلك الحالات تخص خط110 القديم؛ لا تُعرض كاختبارات قبول بعد111.

| نموذج دولة التمويل ومسارات المالك والاستيراد والمرشحات | لا يمنع المرشحات المدعومة؛ يمنع ادعاء تنفيذ هذه الميزة أو تفعيلها | عقد بيانات ومراجعة مخطط، ثم تنفيذ مستقل؛ لا استعارة دولة المانح أو الوجهة |
