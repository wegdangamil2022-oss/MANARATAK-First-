تطابقت ملفات package.json والـlock ومخطط Prisma مع طبقة الاعتماديات المثبتة والمتحقق منها سابقًا عند `a821040`. لذلك أعيد استخدام الاعتماديات وحدها دون تكرار npm ci، وأُحلت حمولة API المبنية الجديدة كاملة، مع فحص كل ملف. هذا ليس ادعاء تثبيت إنتاجي جديد. أُنشئ أرشيف runtime نظيف جديد وفُك إلى `api-boot-root` جديدة؛ نجح تحميل محرك Prisma الأصلي والاعتماديات الخارجية التسع من داخل الطبقة. أرشيف runtime حجمه429394432 بايت وبصمته `9ddb7a93d0c9ef44b4fa82a18af3d6e1b04db0bd5bf5611389c7b4e17497b448`؛ OS Windows x64/Node22.16.0.

شُغّل API من هذه النسخة المفكوكة، وWeb/Admin من حزمهما عبر بوابة HTTPS محلية. قاعدة PostgreSQL16.15 جديدة تمامًا، هوية الخادم `7698386776037789708`، وقاعدة DB-T بدور `post28_app`. السجل **111/111** مطابق بالأسماء والبصمات دون صفوف فاشلة، وتطابق schema. فُحص أيضًا فهرس NULLS NOT DISTINCT مباشرةً، ولم يعتمد الحكم على Prisma diff وحده. جميع تدقيقات الترقية التسعة صفر.

## اكتشاف مهم أثناء إعداد الطبقة

وجد فحص التجميع نسخة `storage/dev-jwt-keys.json` مولدة من تشغيل سابق عند نسخ شجرة runtime سابقة. أوقف المشغل الكاتب إلى الأرشيف المرفوض قبل أي إقلاع منه، وعزل النسخة الجزئية محليًا بصلاحية المستخدم وحده؛ لم تُطبع قيمة المفتاح أو تُرفع إلى Git أو مزود.

استبعدت الحالة الموروثة، وفُحصت قائمة جذور الطبقة المسموحة وغياب `.env` و`lab.env` ومفتاح التطوير قبل التغليف. أُنشئ الأرشيف النهائي النظيف وفُك وفُحص قبل تشغيل API. ملفات API تطابق الحزمة الجديدة بايتًا؛ لا تعديل للنسخة السابقة. استخدم تغليف وحدات الإصدار GNU tar، وتغليف runtime النهائي Windows libarchive tar مع تحقق بعد الفك. هذا إصلاح في حاضنة إعادة الاستخدام التشخيصية خارج المستودع؛ أداة المنتج الرسمية التي تبدأ بتثبيت نظيف لم تتغير. عند إعادة التجهيز، استخدم المسار الرسمي النظيف أو طبقة اعتماديات مختومة خالية من حالة التشغيل، ولا تنسخ مجلدًا شُغّل API داخله على أنه حزمة نظيفة.

## العزل والتنظيف

للتطبيق SELECT على جداول التطبيق، وSessionRecord DML وAuditRecord INSERT اللازمان للمسار فقط. ثبت غياب superuser وCREATEDB وCREATEROLE وBYPASSRLS وschema CREATE وقراءة سجل الترحيل وكتابة الفواتير والمدفوعات. تجهيز المخطط والهوية الصناعية استخدم دور الترحيل المحلي المحدود، منفصلًا عن دور API.

أُوقفت عمليتا API والبوابة بعد المسار، ثم نجح pg_ctl fast stop للمختبر الجديد وتحقق اختفاء PID file. لم تحذف قاعدة أو أرشيفًا سابقًا. لا تعد هذه عملية SIGTERM على Windows إثبات graceful drain إنتاجيًا. لا توجد خدمة منشورة أو مستمرة بعد التسليم.

## ما لم يُكرر وما بقي

أعيد البناء مرة لأن المرشح الحالي يجب أن يحمل SHA الموحد وحمولة API الحالية والترحيل111. أعيد فقط التشغيل والجلسة ومسار المتصفح الأساسي على هذا المرشح والقاعدة الجديدة. لم تُعد فحوص PDF أو مصفوفات R05/R06 أو الحزم العامة. إثباتات gateway/CORS/session refresh-replay السابقة محفوظة بمصادرها، ولا تُجمع مع8 ملاحظات هذه الجولة كعدد حالات جديدة.

المتبقي للقبول الرسمي والنشر:

- CI كامل للمصدر المختار، وأربع حالات تغليف symlink في بيئة تدعمها؛ لم تُضعف assertions أو تحذف الاختبارات السابقة.
- رفع واسترجاع من artifact store معتمد؛ الأرشيفات الفعلية محفوظة محليًا خارج Git، ولا ضمان لاسترجاعها من جهاز آخر.
- runtime/image خاص بنظام الاستضافة المقصود، وgraceful drain ومراجعات إعداد الإصدار والأمان؛ طبقة Windows ليست اعتماد Linux.
- قبول R06 الشامل والميزات المؤجلة بحسب ما سيُفعّل: العمال، الدفع، الشهادات، والإدارة الحساسة. إغلاق R05 المحلي واكتمال R06 الأساسي لا يمنحان قبولًا إنتاجيًا تلقائيًا.

لا عائق تشغيل حرج ظهر في المسار المحلي المقاس؛ **R07 CORE_LOCAL_DIAGNOSTIC_COMPLETE** و**formalR07Acceptance=false**. لا نشر خارجي أو main merge أو C2/promotion ضمن هذه الجولة.
