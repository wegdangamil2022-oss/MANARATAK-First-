# R11 — دفعة قراءة محلية محدودة

اختيرت حدود [التشخيص](../../config/testing/r11-local-read-diagnostic.json) قبل القياس ضمن تفويض المالك بإدارة المشروع ومواصلة R11. هذه سقوف حماية للمختبر، وليست أهداف SLO للإطلاق. لا تغير إعداد R11 الشامل أو تحوّل القيم غير المعتمدة فيه إلى موافقات.

الأداة `scripts/performance/BoundedReadProbe.mjs` تنفذ GET فقط على مساري البحث العام وفلاتر المنح عند 127.0.0.1. لا تتبع redirects، وتفرض بصمة إصدار API، وسقف طلبين في الثانية وتسلسلًا واحدًا، وحدًا أقصى 120 طلبًا للفئة و60 ثانية قياس، ومهلة طلب ثانيتين. تتوقف عند أول خطأ HTTP أو timeout أو تجاوز موارد أو فقد مراقبتها. لا تخفف محدد المعدل. القياسات p50/p95/p99 بطريقة nearest rank، وحجم النقل هو جسم الاستجابة المفكوك وليس بايتات الشبكة المشفرة أو حجم headers.

تُنشأ DB-L داخل cluster PostgreSQL16 جديد، ويُستنسخ إليها dump صناعي سابق بعد مطابقة بصمته، مع تسجيل مصدره وأعداد الصفوف والفهارس وcollation. دور التطبيق للقراءة فقط دون DDL أو صلاحيات مرتفعة. أدوات bootstrap لا تُستخدم لتنفيذ الحمل. لا كتابة مالية أو إرسال أو مزود خارجي، والعمال مغلقون. تُقاس موارد عملية API واتصالات التطبيق؛ pool wait وquery costs ومؤشرات العمال غير مقاسة، ولا تسجل أصفارًا بدلها.

تُستخدم حزمة API الفعلية السابقة c8afe5f فقط إذا أثبت git عدم تغير مصدرها واعتماداته منذ ذلك المصدر، مع تحقق manifest وruntime-layer. يسجل مصدر الأداة الحالي منفصلًا عن مصدر الحزمة؛ لا يعاد وسم إصدارها. Web/Admin لا يحتاجان إعادة بناء لتشخيص قراءة API.

الفئات الخمس الباقية student-writes/admin-scans/imports/finance-stub/worker-queues لا تغلق بهذا الحمل. يلزم توسيع dataset ومراجعة سيناريوهاتها والحدود الخاصة بها قبل تنفيذها. القياس المحلي على عينة صناعية لا يثبت أداء Linux أو حجم الإطلاق أو قياس cold cache؛ warm-up معلن دون تفريغ cache نظام قائم.

النتائج الفعلية تحفظ بعد التنفيذ في ملحق مستقل؛ وجود هذه الوثيقة لا يعني أن الحمل نُفذ أو نجح.

تصحيح منهج التنفيذ قبل القياس التالي: API يرسل بصمة الإصدار في readiness؛ أصبحت الأداة تتحقق من readiness وبصمتها قبل الحمل وكل ثلاث ثوانٍ، وترفض أي بصمة مخالفة إن أرسلتها الاستجابة العامة. أوقفت المحاولة الأولى ذات الطلب الواحد حين غاب header العام، ولم تضعف بوابة الإصدار. ثم أوقفت محاولة الطلبين/ثانية عند أول 429 بعد 72 طلبًا خلال نحو 36 ثانية. هذه نتيجة محدد المعدل الفعلي وليست نجاح أداء. خُفض حمل التشخيص التالي إلى طلب واحد/ثانية وحد 60 طلبًا للفئة، مع بقاء محدد المعدل نفسه دون تعديل. تخفيف الحمل لا يغلق SLO أو يثبت معدل إطلاق أعلى.
