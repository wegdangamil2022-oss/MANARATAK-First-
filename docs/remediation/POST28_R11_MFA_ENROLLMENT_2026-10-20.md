# R11 — تفعيل MFA من الواجهة الفعلية

المسار: دخول مسؤول صناعي بلا MFA ← صفحة أمان الحساب ← بدء الإعداد بكلمة المرور ← تأكيد الرمز ← إلغاء الجلسات ← دخول برمز جديد ← ظهور حالة التفعيل. نُفذ المسار في Edge من Admin المبني عبر HTTPS بشهادة SPKI محددة، داخل قاعدة PostgreSQL16 جديدة ومعزولة.

ثبت رفض كلمة مرور خاطئة برمز 400 دون إنشاء اعتماد TOTP. أعادت الواجهة بدء الإعداد بكلمة صحيحة برمز 200، وعرضت السر ورابط provisioning؛ فُحص تطابقهما في الذاكرة فقط دون حفظهما أو تصويرهما. حُفظ اعتماد pending مشفر، ولم يحتو السجل على السر النصي.

رُفض رمز تأكيد خاطئ برمز 400 وظل الاعتماد غير مفعل. نجح التأكيد الصحيح برمز 200، وثبت اعتماد confirmed وإلغاء جميع جلسات الهوية الجديدة. انتظر الفحص رمز الدورة الزمنية التالية بدل تغيير الساعة أو تعديل بيانات الاعتماد. نجح الدخول برمز جديد، ثم ظهرت حالة «المصادقة الإضافية مفعلة» وstepUpFresh=true. لم يظهر السر أو رابط provisioning بعد إعادة تحميل الصفحة؛ الصورة المحفوظة لهذه الحالة فقط. نجح الخروج وأصبح عدد الجلسات النشطة صفرًا.

لا إدراج لاعتماد MFA مؤكد مسبقًا في هذا الفحص. الحساب وكلمة مروره ومفتاح التشفير صناعية وخاصة بالمختبر. لم تتغير بصمات Consent وBinding والفواتير والقيود التاريخية. استُخدم دور عادي دون superuser/createdb/createrole/bypassRLS/replication؛ أُوقف API وPostgreSQL، ولم تُمس قواعد موجودة. لا أخطاء صفحة أو HTTP5xx.

مصدر المشغل 6d440363adb1477101402f00371e2319c3aae84f، وAdmin المبني 50e109e3ece76c6b5acb832be9fcd747450821cb، وAPI/Web المحتفظ بهما c8afe5f253d132f671ecd035a0330de7794b6ee8 بعد بوابة التحقق من عدم تغير مصادرهما واعتماداتهما. لم يُعد بناء أي تطبيق لهذا الفحص ولم يُعد فحص الدخول السابق مستقلًا؛ الدخول والخروج هنا جزء من إثبات إلغاء جلسة التفعيل والحصول على جلسة جديدة. هذه أدلة تكامل محلي بمصادر معلومة، وليست مرشح إصدار موحدًا أو قبول حمل/SLO.

[الأدلة وبصمات الملفات](../reviews/evidence/post28/6d440363adb1477101402f00371e2319c3aae84f/r11-mfa-enrollment/evidence-index.json). نُقلت مخرجات الفحص الفعلية وصورة الحالة النهائية والمشغلات كأدلة؛ ملفات كلمات المرور والسر ومفاتيح TLS وقاعدة البيانات مستبعدة.

المتبقي في R11: نتيجة CI/Linux بعد إصلاح ترتيب الطلبات، حمل وبيانات ممثلان وأهداف SLO معتمدة، قياس pool wait، ودورة CMS الكاملة وخط الاستيراد والمستهلكون الحقيقيون. هذا الفحص لا يثبت step-up منفصلًا أو تعطيل MFA أو استرداد الحساب، ولا يعيد تصنيف الأدلة السابقة.

تحديث CI للفرع عند 6d44036: نجحت بوابات المصدر والبناء واسترجاع الحزم. أثبتت محاولة Linux تجاوز 429 ودخول 200 وCSRF200، ثم أعاد زوج الكتابة الأول 200 و409. توقف الفحص عند assertion تفاصيل الزوج قبل احتساب نجاحه، وألغى الجلسة بنجاح وأغلق الحاويتين والشبكة. طابقت بصمة أرشيف أدلة GitHub. لا نجاح للحمل أو CI الشامل؛ السبب قيد التشخيص بفحص الزوج الأول وحده. نجاح صورة Linux في تشغيل pull_request ذي الخطوات المتخطاة لا يغني عن تشغيل الفرع.

سبب assertion موثق وإصلاحه 0402c97f6b5e93e7810a1053c6a43f0d410961f5: يرسل StudentWorkspaceRouter خطأ VERSION_CONFLICT؛ ويحوّله canonicalProblemDetailsMiddleware عبر legacyErrorToProblem إلى body.code مع body.status=409، فلا يوجد body.error في الاستجابة النهائية. كان فحص Linux يقرأ الحقل القديم. أصبح يشترط الكود الدقيق وحالة المشكلة 409؛ ويظل يرفض تعارضًا غير متعلق بالإصدار، أو نجاحين، أو فقد التحديث، أو صيغة خطأ قديمة. نجح اختبار العقد المباشر وحده (حالة واحدة)، ثم نجح فحص محول Problem Details الفعلي مع الأداة. لم تُعد المجموعات العامة. نجح فحص جودة المصدر.

التحقق المحلي الإضافي محدود ولا يسجل نجاح HTTP بعد الإصلاح: المحاولة الأولى استخدمت دور إدارة دون student، فأعادت 403؛ صُحح تجهيز الهوية. في المحاولة التالية لم يجهز API، وكان PostgreSQL قد خرج قبل محاولة الإغلاق، فرفض حارس PID تنفيذ الإغلاق بدل استهداف عملية غير متحققة. أكد pg_ctl status عدم وجود خادم، ولم يكن منفذ المختبر مستمعًا. لم يُتجاوز حارس المصدر النظيف أو PID؛ حُفظ العمل في commit قبل إنشاء المختبر. لم يثبت سبب خروج العملية ولا تنفيذ زوج الكتابة في هذه المحاولة، فلا ادعاء بذلك. لا إعادة متشابهة لمشكلة البيئة.

الحالة الحالية: تفعيل MFA من الواجهة مثبت، وإصلاح فحص العقد مثبت باختباره ومحوّل الأخطاء الفعلي؛ تشغيل Linux بعد هذا الإصلاح ما زال مطلوبًا. CI المصدر6d44036 فشل في assertion السابق رغم نجاح المصدر والبناء والاسترجاع؛ لا يُسجل PASS شامل. [أدلة الإصلاح وحدود التحقق](../reviews/evidence/post28/0402c97f6b5e93e7810a1053c6a43f0d410961f5/r11-wire-contract/evidence-index.json).

تحديث Linux للمصدر 4b8e22f4cad6c5cdca384cf3e273c6d5cf97d61b: نجح تشغيل push 39475394144 بما فيه البناء واسترجاع الحزم وتشغيل API/Web/Admin من المصدر نفسه، واتصال PostgreSQL16 ورحلة المتصفح العامة. نجح فحص التزامن: 10 أزواج، كتابة واحدة محفوظة وتعارض إصدار متوقع واحد لكل زوج، وإعادة الفائز دون إصدار إضافي؛ صفر أخطاء غير متوقعة، وخروج موثق بصفر جلسات. طابقت بصمة أرشيف الأدلة قيمة GitHub المنشورة. p50=31.52ms، وp95/p99=159.51ms لزمن إتمام الزوج من 10 عينات فقط، وليست حدود SLO مثبتة. poolWaitMs غير مقاس؛ queryRoundTripMs موثق منفصلًا. أُغلقت الحاويتان والشبكة دون مساس بقواعد سابقة. [الأدلة](../reviews/evidence/post28/4b8e22f4cad6c5cdca384cf3e273c6d5cf97d61b/r11-linux/evidence-index.json).

بهذا ثبت إصلاح تداخل ميزانية الطلبات في فحص Linux. لم يُستخدم نجاح تشغيل pull_request الذي تخطى فحوص المتصفح بديلًا عن تشغيل push. المتبقي للقبول الشامل: حمل وبيانات ممثلان وSLO، قياس حجز الاتصال، ودورة CMS المبنية كاملة وخط الاستيراد والمستهلكون الحقيقيون. نتيجة تشغيل المصدر المذكور لا تُنسب تلقائيًا إلى commit التوثيق اللاحق، وفحص MFA المحلي يظل بمصادره المنفصلة المعلنة.
