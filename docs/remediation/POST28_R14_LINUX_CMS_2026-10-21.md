# R14 — رحلة CMS العربية والإنجليزية من حزم Linux موحدة

المرشح المتحقق `6f7b68572f007a45d10263759800d8cbbfd49135` على `feat/post28-r07-artifact-preparation`. نجحت رحلة Linux المحددة ووظائف CI الست. هذه مراجعة تشخيصية محلية، ولا تغير قرار NO_GO أو قبول R13/R14 الرسمي. تحفظ الأقسام التالية تاريخ المحاولات السابقة دون تحويل نتائجها الفاشلة إلى PASS.

## التنفيذ

أضيف ملف تشغيل اختياري `--r14-admin-cms` إلى مشغل Linux المعزول، مع ثلاث هويات صناعية منفصلة للتأليف والمراجعة والنشر. ينفذ المتصفح إعداد MFA وتأكيده، ويتحقق من إلغاء الجلسة، ثم يسجل الدخول بكود خطوة زمنية جديدة. لا تُحقن موافقة MFA مسبقة. يشغل API/Web/Admin من حزم المصدر نفسه، ويربطها بقاعدة PostgreSQL16 جديدة وصورة API محدودة الصلاحيات وشبكة داخلية. لا اتصالات بمزود خارجي أو قاعدة سابقة.

المسار المثبت لكل من العربية والإنجليزية: مسودة مخفية، إرسال للمراجعة، رفض اعتماد المؤلف، مراجعة بهوية ثانية، نشر بهوية ثالثة، بقاء snapshot المنشورة عند تعديل المسودة، ثم سحب واستجابة404 من API المحتوى. العربية وحدها مفعلة للعرض العام: ثبت ظهورها في HTML وWeb واختفاؤها بعد السحب. الإنجليزية تبقى محجوبة في HTML العام مع noindex/nofollow، ويعيد Web مسارها للعربية؛ لا يُدعى عرض عام إنجليزي. ثبت أيضًا إلغاء جلسات الهويات ومطابقة بصمات الجداول المحمية قبل/بعد. المختبر جديد؛ الجداول المحمية الخمسة فارغة، فلا يثبت هذا الفحص حفظ صفوف تاريخية موجودة.

توسعة صلاحيات قاعدة التشغيل مقيدة بخيار `--r14-admin-cms-fixtures` للمختبر وحده، وتقتصر إضافاتها على Credential وسجلات CMS المطلوبة. لا DDL أو تعديل سجل migrations أو إضافة صلاحيات مال وConsent وBinding. لم تتغير migrations أو guards أو assertions الإلزامية.

جُهز ملف التشغيل في `f1af666`، ثم صُححت عقود أداة الاختبار في `83ce0e5` استنادًا إلى رحلة Admin السابقة الناجحة: أصل النشر المرجعي بلا منفذ، مسار HTML تحت public/cms، واسم textarea الذي يتضمن قيمته. لا تغيير في مصدر API/Web/Admin بين هذين الالتزامين أو منذ `fb1a375`.

## الدليل المحلي المحدد

نجح فحص قاعدة PostgreSQL16 صناعية جديدة على Windows للمصدر `f1af666`: ثلاث هويات، دور post28_app بلا صلاحيات مرتفعة، إعداد وتأكيد MFA الحقيقي المشفر عبر PrismaMfaGateway، رفض إعادة استخدام الكود المستهلك، وعدم تغيير hash كلمة المرور. إضافة الصلاحيات وزرع الهويات لم يتغيرا في `83ce0e5`. هذا فحص profile والصلاحيات؛ لا يُسجل رحلة متصفح أو Linux بهذا الدليل.

المحاولة الأولى أوقفت الأداة بسبب استدعاء اسم دالة غير موجود `isEnrolled`؛ صُحح إلى العقد الفعلي `enabled` ثم أُعيد هذا الجزء فقط في مختبر جديد. احتُفظ بفشل الأداة وإيقاف المختبرين؛ لم يُغير المنتج لتجاوز الفشل.

اختبارات الدفعة: اختبار حدود الصلاحيات الاختيارية الجديد ناجح، وعشرة اختبارات CI architecture ناجحة لأن workflow تغير. lint للملفات المعدلة بلا أخطاء، وفحص environment inventory يثبت 327 اسمًا دون تغيير. لم تُعد مجموعات محلية غير متأثرة أو بناء الواجهات محليًا؛ البناء المحدد بالمرشح ينفذ في CI.

## CI والحزم والتراجع

اكتمل [CI39599847197](https://github.com/wegdangamil2022-oss/MANARATAK-First-/actions/runs/39599847197) للمصدر `fb1a375` بنجاح الوظائف الست. استُرجع دليل Linux ودليل التحقق من الحزم وتحققت بصمتهما من metadata تخزين GitHub. دليل Linux يثبت readiness للوحدات الثلاث، تشخيص التزامن والتصفح العام، ثم API exit=0 بعد docker stop فعلي، وتنظيف الحاويات وقاعدة المختبر والشبكة. لا يحتوي ذلك الدليل رحلة CMS الجديدة.

تنزيل حزم الإصدار الكبيرة إلى Windows تعثر بمهلة النقل؛ الملف الجزئي غير معتمد ولم يُفك. CI السابق أثبت استرجاع الحزم والتحقق من manifest وكل وحدة داخل Actions. لا يُعد ذلك استرجاعًا محليًا كاملًا ولا بروفة تراجع.

أثبتت مقارنة المصدر أن `fb1a375` سلف المرشح الحالي، وأن مسارات API/Web/Admin/packages/vendor وملفات الحزم متطابقة. يحتفظ هذا المرشح بإصلاحات صحة العمال وتسليم الشهادات؛ لا يُختار `19b6a6d` الذي يفتقد إصلاحات العمال. هذه أهلية مصدر أولية؛ لا تثبت تبديل حزم سابقة أثناء تشغيل Linux أو تراجعًا لتنفيذ مختلف. بروفة التراجع المحددة ما زالت مطلوبة.

تشغيل المرشح الحالي [CI39601999968](https://github.com/wegdangamil2022-oss/MANARATAK-First-/actions/runs/39601999968) قيد المتابعة. لا تُسجل رحلة CMS ناجحة حتى استرجاع نتيجتها وتنظيفها. أُلغي تشغيل `f1af666` المتجاوز بعد رفع إصلاح عقود الأداة، ولم يُعتبر ناجحًا.

[فهرس الأدلة وبصماتها](../reviews/evidence/post28/83ce0e56af89ab05bdbf99fb18ef213b22d48645/r14-linux-cms-preparation/evidence-index.json). يبقى مطلوبًا بعد هذا المسار: بروفة التراجع بالإشارات الفعلية والحزم المحددة، وحدود الحمل الممثلة وpool checkout، وبوابات الاستضافة والثقة والإصدار المعتمدة. لا نشر أو ترقية أو توقيعات مختلقة.

## تشخيص الفشلين وإصلاحهما

فشل CI39601999968 في اختبار سلبي لحارس حدود المتصفح، قبل تشغيل Linux. كان الحارس يتحقق من وجود تصريح runtime في الوظيفة كلها، فأخفى وجود رحلة ثانية سحب التصريح من الأولى. أصلح `6d64b30` الحارس ليتحقق من الفرع والتصريح والأمر المسموح لكل رحلة؛ لم يُحذف الاختبار السلبي أو يُخفف. نجحت اختباراته الست واختبار profile المباشر، ثم مراجعة الوثائق9/9. لا تُعد رسائل DATABASE_UNAVAILABLE وheaders من الاختبارات المتعمدة في annotations أسباب فشل مستقلة؛ المقتطفات نفسها تبين نجاح ملفاتها.

اجتاز `6d64b30` اختبارات المصدر والبناء واسترجاع الحزم والترجمة وإعدادات النشر وRedis. في CI39604796980 أقلعت الوحدات الثلاث من SHA واحد على Linux/PostgreSQL16 بدور التشغيل العادي. أثبت السجل تفعيل MFA وتأكيده ثم دخولًا جديدًا للحسابات الثلاثة، ومراجعة المحتوى العربي ونشره وظهوره في HTML العام وWeb المبني. فشلت العودة إلى Admin بسبب استنفاد طلبات المختبر المتتابعة الحد الحالي100/60s؛ عاد auth/me برمز429. لا سحب مثبت ولا إنجليزية مثبتة بهذه المحاولة. نُظفت الحاويات والقاعدة والشبكة، وأغلق API برمز0 خلال133ms.

أضيف في `282a7aa` منظم طلبات للأداة فقط: تحجز سياقات المتصفح المشتركة60 طلب API لكل61000ms، قبل الإرسال، مع مهلة متصفح تسمح بانتظار نافذة الطلبات. لا تعديل لمحدد المعدل في الخادم ولا إعادة طلب مرفوض؛ أي429 يبقى سبب فشل صريحًا. نجح اختبارا تزامن حجز121 طلبًا ورفض إعداد يتجاوز السقف المحلي. [CI39625777899](https://github.com/wegdangamil2022-oss/MANARATAK-First-/actions/runs/39625777899) لهذا المرشح قيد المتابعة؛ لا يُسجل نجاح الرحلة بالاعتماد على إصلاح الأداة وحده.

## سياسة الإنجليزية الفعلية

وصلت محاولة `282a7aa` إلى السحب العربي واختفاء النسخة العامة وWeb، ثم مراجعة ونشر النسخة الإنجليزية داخليًا، بلا429 في سجل HTTP. فشلت أداة التشخيص عند افتراض200 للصفحة الإنجليزية؛ أعادت404 وفق السياسة الفعلية في `packages/shared/src/localization/readiness.ts`: `PUBLIC_ENGLISH_COPY_READY=false` وقائمة عرض القالب العام `['ar']`. لم يكن صحيحًا افتراض فتح الإنجليزية اعتمادًا على إمكان تأليفها ونشر snapshot لها. أُوقف API برمز0 خلال153ms ونُظفت القاعدة والحاويات والشبكة. [النتيجة الفاشلة محفوظة](../reviews/evidence/post28/282a7aa791cb1363f8a0cc29ee661fb3acf5cb9e/r14-linux-cms-runtime/evidence-index.json)؛ لا تُعاد تسميتها PASS.

أصبح المشغل في `d927710` يقرأ السياسة نفسها بلا override: تبقى اللغة المفعلة ملزمة200 وعرض النص، وتلزم المغلقة404 وnoindex/nofollow وإعادة Web إلى اللغة العربية دون عرض النص الإنجليزي. تُفحص snapshot الإنجليزية المنشورة من API المالك، وحجب تعديل المسودة، ثم الأرشفة و404 من API؛ لا يُدعى عرض إنجليزي عام. نجح اختبار عقد التسليم الجديد، بما فيه رفض200 للغة المغلقة ورفض404 للغة المفعلة وغياب توجيه منع الفهرسة. لا تغيير في السياسة أو مصدر التطبيقات أو guards. [CI39628696516](https://github.com/wegdangamil2022-oss/MANARATAK-First-/actions/runs/39628696516) للمرشح قيد المتابعة.

تعطيل الإنجليزية استثناء قبول رسمي باقٍ: لا يمنع تشغيل المختبر العربي أو سير التحرير الإنجليزي، ويمنع وصف الإصدار العام بأنه ثنائي اللغة مكتمل. فتحها يحتاج إكمال جاهزية النصوص ومراجعة بوابة اللغة؛ لا تُفعّل قيمة readiness لتجاوز فحص.

توقف CI39628696516 قبل إنشاء مختبر CMS لأن استيراد `@manaratak/shared` طلب shared/dist غير المبني في وظيفة Linux المستقلة. وظيفة المصدر واسترجاع الحزم وبقية الوظائف الخمس نجحت؛ لا ملف نتيجة CMS لهذا المصدر. صُحح الاستيراد إلى ملف سياسة readiness.ts مباشرة عبر tsx الموجود، ونجح تحميل الوحدة والتحقق من قائمة ar محليًا دون بناء shared أو تغيير السياسة. الدليل يحتفظ بخطأ الاستيراد وحده، دون سجل environment. هذه معالجة أداة تشغيل؛ لا تُسجل نجاح رحلة المتصفح حتى فحص المرشح اللاحق.
