الحدود المحددة قبل القياس: تسلسل واحد، نصف عملية/ثانية، 30 عملية خلال دقيقة لكل فئة، مهلة عملية ثانيتان، CPU أقل من 80% وذاكرة Node مجمعة أقل من 1GiB واتصالات دور التطبيق لا تتجاوز 10. يوقف فقد مراقبة الموارد التنفيذ. تدخل كلفة المراقبة في ضبط المعدل، وتنتظر الأداة استقرار الكتابة قبل الانتقال إلى عملية أخرى عند تجاوز المهلة. لا يتغير محدد معدل التطبيق. هذه أسقف حماية للمختبر وليست أهداف SLO.

كتابات الطالب مرت عبر API المبني ومصادقة cookies وCSRF. ثبت حفظ 30 إصدارًا، وأن إعادة أول أمر لا تزيد الإصدار، وأن الطالب يتلقى 403 من مسار الإدارة. صفحات الدعم قاست نموذج القراءة الحقيقي وcursor موقعًا على 81 مساحة صناعية؛ لم تظهر metadata الخاصة. هذا لا يثبت جلسة Admin/MFA فعلية أو عزلًا مؤسسيًا.

الاستيراد قاس إنشاء 30 هوية مصدر و30 إيصال URL أولي من خلال المستودع الفعلي، مع منع تكرار الهوية عند إعادة الطلب. المزود FILE صناعي خامل؛ خط الاستيراد الكامل والمراجعة والنشر غير مقاسين. لا اتصال بنطاق example.invalid.

المال قاس 30 فاتورة صناعية: إنشاء ثم إصدار ثم credit بقيمة 25 من 100. تحقق الرصيد 75 وتوازن القيود وعدم زيادة ledger/command/outbox/audit عند إعادة الأمر. لا مزود دفع أو تحويل أو FX مسجل. النتائج لعملية application مركبة مع فحوص تحقق إضافية، وليست زمن HTTP أو مزود دفع.

الطابور استخدم claim/renew/complete الفعلية لنطاق صناعي فريد، ومصرف تسليم Audit خامل append-only. عولجت 30 رسالة دون فقد lease أو رسائل متبقية، ولم تتكرر نتيجة التسليم عند إعادة الرسالة. هذا لا يقيس المستهلكين الحقيقيين كافة. حُفظ lag لكل رسالة داخل observations؛ يتضمن انتظار حمل التشخيص المتسلسل.

أثبتت بصمات الصفوف السابقة بقاء Consent وBinding والفواتير والقيود التاريخية بلا تغيير. دور الحمل عادي دون superuser أو إنشاء قاعدة/دور أو bypassRLS أو replication؛ لا يعدل migrations ولا Audit/ledger السابقين. استُخدم دور تجهيز منفصل لإنشاء الصفوف الصناعية داخل هذه القاعدة وحدها. أُغلقت API وPostgreSQL بعد التنفيذ. لم تمس Neon أو إنتاج أو قواعد سابقة أو main.

تعطلت المحاولة الأولى قبل القياس بسبب مسار Git المفقود في بيئة العامل؛ حُفظ سجلها وإغلاقها. أصلحت مسارات الأدوات ومفتاح cursor الصناعي قبل القياس. توقفت عمليات المحاولة التالية قبل إنشاء نتائج سيناريو، وتعذر إثبات سبب إنهاء العمليات؛ استُعيد تشغيل هذا cluster الجديد نفسه بعد مطابقة هويته وبصمة binary، مع تبديل كلمة مرور دور الحمل والتحقق من runtime. لا تُعد هذه المحاولات PASS، ولا أُعيد سيناريو ناجح.

نجحت الحالات الثلاث المحددة لأداة السيناريو؛ أُعيدت مرة واحدة بعد تعديل احتساب زمن المراقبة ضمن المعدل. لا إعادة لمجموعات R06–R10 أو قياسي القراءة. فحوص GitHub الـ23 للمصدر السابق 6b9c672 نجحت، ومنها Linux واسترجاع الحزم؛ لا تنسب إلى مصدر هذه الدفعة تلقائيًا.

الحالة: سبع فئات لها تشخيص محلي محدود، مع تفاوت حدود السيناريوهات المبيّن أعلاه. قبول R11 الشامل مفتوح: dataset ممثل للإطلاق، أهداف SLO معتمدة وحمل ممثل وتزامن، Linux load فعلي، pool wait وتكلفة PostgreSQL ومراقبة موارده، Admin/MFA وخط الاستيراد والمستهلكون الحقيقيون. موارد CPU/memory هنا تخص عمليتي Node وليست قياس PostgreSQL أو الخادم كله. عينات p99 الثلاثين غير كافية لتقدير ذيل حمل إطلاق. ضوابط مزود R10 تبقى معلقة لعدم وجود حساب استضافة معتمد.

نجحت حراسة جودة المصدر وفحص الأسرار؛ طابقت بصمات الملفات العشرين داخل Git index البايتات الأصلية، ولم تظهر قيم اعتماد الطالب الصناعي في الأدلة. لقطة CI للمصدر 399f816 محفوظة: لا فشل مسجل، وبعض الفحوص قيد التشغيل عند أخذ اللقطة. لم يُدّعَ نجاح CI الكامل لهذه الدفعة. إحصاءات استعلامات Prisma محفوظة لعميل أداة السيناريو فقط وتستثني استعلامات API المبني؛ لا تعادل كلفة SQL أو انتظار pool.
