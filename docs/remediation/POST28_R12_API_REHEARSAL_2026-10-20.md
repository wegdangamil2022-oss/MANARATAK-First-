# R12 — بروفة تراجع API فعلية مع حفظ البيانات

**نجحت بروفة API المحلية المحددة. R12 غير مغلقة: العامل السابق وdrain/lease وأحداثه الأحدث واعتماد canary الإنتاجي ما زالت غير مثبتة.** استثناءات R11 وحالات المراحل السابقة محفوظة.

استُرجع أرشيف المرشح 4b8e22f من مخزن موصل GitHub عبر عميل Windows بعد تعطل curl؛ طابقت البصمة المنشورة bc43f19e0435e834890af468ef340c0832f967beab403d2054116200493ba327. تحققت وحدات manifest الحالية والسابقة وفُك API منهما في مسارين جديدين؛ طابقت بايتات server.cjs بعد التنفيذ محتواها داخل كل tar. السابق c8afe5f والحالي 4b8e22f متطابقان في مصادر API/worker وschema/lock: هذا اختبار رجوع artifact/config/session/receipt، وليس إثبات رجوع بين تطبيقين مختلفين. ظلت حزم Admin/Web خارج نطاق التراجع.

نُفذت البروفة في cluster PostgreSQL16 جديد وقاعدة صناعية جديدة بدور post28_r12_actor دون superuser/createdb/createrole/replication/bypassRLS. لم تُنفذ migration أو down migration. طبقة اعتماد Windows المقفلة من c8afe5f مشتركة بعد تحقق بصمتَي schema/lock وPrisma/native modules؛ لا يُعاد وسمها 4b8e22f ولا يعد هذا بديلًا لصورة إصدار Linux موحدة.

## النتيجة التشغيلية

- دخل الحساب الصناعي عبر HTTPS وشهادة CA محلية صحيحة، وحُفظت cookies بخصائص Secure/HttpOnly/SameSite=Strict.
- كتب API الحالي workspace مرة واحدة وأنتج receipt. ثبت توقف عمليته وإغلاق المنفذ قبل بدء API السابق على routing نفسه.
- قبل السابق الجلسة الموجودة وCSRF عبر مفاتيح صناعية مشتركة خاصة بهذه البروفة. أعاد الأمر القديم بنفس idempotency key برأس Idempotency-Replayed=true واستجابة مطابقة دون زيادة الإصدار.
- رفض السابق الكتابة بلا CSRF برمز403، ورفض وصول الطالب لمسار الإدارة برمز403. نجح الخروج وأصبح عدد جلسات الهوية النشطة صفرًا.
- طابقت كل الصفوف الأصلية في الجداول المحمية قبل/بعد. بقيت الجداول المالية والموافقات وBinding والنشر وسجل migrations مطابقة بالكامل؛ وطابقت outbox وAPI receipts كلها لقطة ما بعد الكتابة الحالية حتى نهاية البروفة. أضيف صفا Audit خلال الفحوص اللاحقة؛ حُفظت كل صفوف Audit الأصلية ولم تُقَس سببية الإضافتين لكل طلب منفرد. لا ادعاء بمنع إضافة سجل تدقيق مشروع.
- ثمانية طلبات canary خلال 2.690 ثانية، ضمن الحد المحلي 24 طلبًا وتزامن واحد ونافذة أقصاها60 ثانية؛ هذه ميزانية أمان وليست قياس حمل أو اختبار60 ثانية. readiness ووقت فحص الاستماع خارج عداد طلبات canary، وبحدود مستقلة.

## العزل وإغلاق المختبر

حزمة API الأصلية تستمع افتراضيًا على0.0.0.0؛ لذلك أضيف preload محلي يفرض127.0.0.1 دون تغيير بايتات الحزمة. أثبت Get-NetTCPConnection عنوان ومنفذ كل عملية. البروفة الوظيفية الأولى نجحت قبل إضافة هذا الإثبات، ولا تُستخدم لإثبات عزل الشبكة. توقفت محاولتان قبل canary: صيغة --import على Windows كانت تحتاج file URL، ثم لم يكن powershell.exe موجودًا في PATH المحدود؛ صُححتا بمسار file URL ومسار Windows مطلق، ونجح فحص preload/رصد المنفذ دون قاعدة قبل المحاولة النهائية. حفظت المحاولات ونتائج إغلاقها. إعادة البروفة كانت بسبب تغيير العزل وإصلاح مشغلها، لا إعادة مجموعات ناجحة غير متأثرة.

استُخدم إنهاء عملية Windows المملوكة بعد انتهاء الطلبات؛ ثبت إغلاق المنفذ قبل البدء التالي. **هذا لا يثبت graceful SIGTERM drain لعامل Linux.** العمال والمزودات الخارجية معطلة. أُغلقت عمليتا API وبوابة HTTPS وPostgreSQL؛ لم تتغير قواعد سابقة أو Neon أو الإنتاج أو main. مفاتيح JWT/CSRF وTLS وcookie jar وبيانات الاعتماد والنسخ الصناعية مستبعدة من Git.

لم يُجرّب تنزيل ملف أصل أو صلاحية grant عبر النسخة السابقة في هذه البروفة، ولم تُثبت مطابقة بايتات ملفات الأصول. حُفظت صفوف Consent وBinding المحددة؛ تحقق تسليم الأصول وgrants وسلوك الروابط المتقاعدة بعد الرجوع يبقى ضمن القبول المتبقي، ولا يغطيه تطابق الجداول وحده.

## ما تغير ونقطة الاستئناف

أصبحت أداة inspect-post28-rollback-source.mjs تقبل مسار الحزمة الحالية اختياريًا وتتحقق من وحداتها وهويتها قبل وصف زوج الحزم بأنه جاهز للتجربة؛ لا تخلط جاهزية المدخلات مع نجاح التشغيل. نجح فحص الزوج الفعلي، ورُفض تمرير الحزمة السابقة بدل الحالية قبل كتابة output أو اتصال بقاعدة. لم تُعد اختبارات بوابة R12 الناجحة أو مجموعات R06–R11.
