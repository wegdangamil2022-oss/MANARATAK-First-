# R11 — فحص Linux وإصلاح دخول Admin

أُصلح خلل وظيفي ظهر في المتصفح الفعلي: نموذج Admin كان يسمح بالإرسال أثناء فحص الجلسة الأولي. بعد رفض الجلسة القديمة، يلغى request controller المشترك، وقد يُلغى الدخول قبل وصول POST إلى الخادم. سجل المتصفح السابق يثبت طلبات me/CSRF/refresh دون POST login، وفشل اختبار الزر قبل التصحيح. أصبح الزر معطلًا أثناء loading، ومعه guard داخل submit يمنع الإرسال البرمجي أو المكرر أثناء busy. بقيت CSRF وMFA والإلغاء عند تغير الجلسة كما هي.

مصدر الإصلاح **50e109e3ece76c6b5acb832be9fcd747450821cb**. نجحت حالتان محددتان: منع الإرسال أثناء bootstrap والسماح بعده، وتمرير رمز MFA مع عرض رفضه الفعلي. أُعيد الملف بعد نقل الاختبارات خارج نطاق TypeScript الخاص بالتطبيق؛ فشل الفحص الأول بسبب declaration الخاصة بأداة test renderer، وليس المنتج. نجح فحص TypeScript لـAdmin بعد النقل، وlint المحدد وحراسة جودة المصدر. أُزيل تحذير any في تعريف بيئة الاختبار دون تغيير سلوك المنتج.

فحص Edge الفعلي عبر HTTPS وشهادة SPKI محددة أثبت: رفض كلمة المرور بلا OTP برمز 401 دون إنشاء جلسة؛ قبول OTP صحيح؛ ظهور CMS من Admin المبني وقراءة بياناته؛ MFA enabled وstepUpFresh؛ رفض إعادة استخدام OTP برمز 401 دون جلسة إضافية؛ وإلغاء الجلسة بالخروج. طابقت بصمات Consent/Binding والفواتير والقيود التاريخية الأصل. لا page errors أو HTTP5xx في الفحص. [الأدلة والبصمات والصورة](../reviews/evidence/post28/50e109e3ece76c6b5acb832be9fcd747450821cb/r11-admin-mfa/evidence-index.json).

أُعيد بناء **Admin وحده**. API/Web من c8afe5f بعد إثبات عدم تغير مصادر API والاعتمادات وWeb. خادم التشخيص يحتفظ ببصمة كل وحدة منفصلة؛ لا يعيد وسم الحزمة القديمة. هذا تكامل محلي بمصدرين معلومين، **وليس مرشح إصدار موحدًا**. التحقق من المرشح الموحد يبقى عبر CI. بيانات MFA عبارة عن اعتماد TOTP مشفر مجهز لهوية صناعية جديدة؛ لا ادعاء لاختبار واجهة enrollment أو دورة CMS التأليف/المراجعة/النشر/السحب.

المختبر PostgreSQL16 جديد، والحمل بدور عادي دون superuser أو إنشاء قواعد/أدوار أو bypassRLS أو replication. تجهيزه فقط بدور منفصل. أُغلقت الخدمات والقاعدة. لا إنتاج أو Neon أو بيانات مستخدمين أو مزود مؤثر. حُفظت محاولتا التجهيز غير المنفذتين: description ناقص في دور fixture، ثم متصفح Chromium غير مثبت؛ استُخدم Edge الموجود. حُفظ فشل bootstrap الحقيقي ونجاح الإصلاح، ولا تعاد سيناريوهات الفئات السبع السابقة.

أُضيف إلى مختبر Linux القائم فحص محدود لـ10 أزواج من كتابات متزامنة خلال 60 ثانية، بتزامن كتابتين، وميزانية CPU80% لكل من API/PostgreSQL وذاكرة API768MiB وPostgreSQL1GiB واتصالات التطبيق حتى10. يشترط نجاح كتابة واحدة ورفض الأخرى بتعارض الإصدار المحدد، وحفظ إصدار واحد، وإعادة الفائز دون أثر جديد. يسجل EXPLAIN ANALYZE BUFFERS لاستعلام مساحة الطالب، وإحصاءات pg_stat_database وموارد الحاويتين. زمن SELECT1 يسمى queryRoundTripMs؛ poolWaitMs يبقى null لعدم توفر قياس حجز اتصال مستقل. العينات ليست إثبات SLO إطلاق.

نجحت ثلاث حالات محددة لأداة Linux، ومنها رفض نجاح الكتابتين أو الخطأ المتنكر كتعارض ورفض قياس الموارد المفقود أو المتجاوز. فشل CI للمصدر 4aed744 قبل البناء لأن حارس الوثائق يجيز أعلام المختبر القديمة فقط؛ أصلح 33b6daa قبول الصيغة الدقيقة --r09-public --r11-contention، مع بقاء الأعلام الاعتباطية والتركيبات الأخرى مرفوضة. نجح اختبار الحارس وحده، ومحقق W7 اللازم 9/9 و6/6. لا تخفيف assertion أو تجاوز بوابة. أُلغي تشغيل push القديم a295ca3 المستبدل لتوفير التكرار، ولا يسجل نجاحًا.

حالة Linux: **مضاف إلى CI؛ النتيجة الفعلية لم تثبت في هذه الوثيقة بعد**. آخر لقطة للمصدر50e109e قيد التشغيل؛ لا إعلان PASS شامل. المتبقي: نتائج Linux/CI المصدر الموحد، بيانات وحمل ممثلان للإطلاق وأهداف SLO، قياس pool wait، واجهة MFA enrollment ودورة CMS الكاملة وخط الاستيراد والمستهلكون الحقيقيون. ضوابط النسخ لدى مزود R10 تبقى غير مثبتة لعدم وجود مزود معتمد.

تحديث CI للمصدر 33b6daa: نجحت بوابات المصدر والبناء واسترجاع الحزم. طابق أرشيف أدلة Linux بصمته المنشورة. نجحت رحلة R09 العامة، ثم بلغ طلب تسجيل دخول R11 حد الطلبات برمز 429؛ أُوقف الفحص دون تنفيذ أزواج الكتابة، وأُغلقت الحاويتان والشبكة. صُحح ترتيب المختبر: يبدأ R11 أولًا من مستند health/build ساكن، دون طلبات bootstrap لواجهة الدخول، ثم تبدأ الرحلة العامة بعد نافذته المحددة بـ60 ثانية. لم تتغير حدود المعدل أو حمايات المنتج. نجح فحص صياغة المشغل وجودة المصدر؛ إثبات التنفيذ بعد تعديل الترتيب ما زال معلقًا بنتيجة CI الجديدة.
