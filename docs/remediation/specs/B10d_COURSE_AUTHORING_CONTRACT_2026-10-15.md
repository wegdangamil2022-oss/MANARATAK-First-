# B10d — Course authoring

Owner COURSES, existing CourseCurriculumUseCases / LearningPathUseCases and CourseAdminCommandUseCases transaction boundary. Work order: question banks, learning paths, then draft ordering/retirement UI. No schema, parallel store, new approval role, provider or student-data operation.

RBAC is existing admin:courses:manage on admin course routes and client controls. Every mutation supplies authenticated actor, reason and If-Match for existing aggregate; business/audit/outbox/checkpoint commit together. API rejects stale version before child writes. Content create never publishes the course.

Question banks: create/edit DRAFT bank in a mutable native course, attach questions by the same owner bank ID; answer data is admin-only. Existing quiz editor remains. Reject bank archival whenever question references exist, including archived questions; no reference or attempt history is removed to enable archival. Never hard delete questions/answers or change student attempts. Bank title/question prompt required, question types/points follow existing contracts; no invented correct answers. Published/archived/rejected courses reject authoring.

Learning paths: create DRAFT with native course IDs from paged owner picker. Edit title/description/order/required/prerequisites only while DRAFT. Reject duplicates, invalid positions, missing/self/cyclic prerequisites and non-native courses. Every edit appends a LearningPathVersion and course membership snapshot; old versions remain unchanged. Review readiness and publication reuse existing owner status transitions, requiring nonempty graph and published courses. Published/archived paths cannot be edited; archive preserves enrollments pinned to their learningPathVersion. No new delete/unpublish path command or progression rewrite. Path listing bounded to pages.

Draft structure: reorder modules and per-module lessons with an exact permutation of all existing IDs, never recreating them. Removal invokes existing archival commands (module retires descendants; lesson retires attached quizzes; quiz/question are archived). Old CourseVersion snapshots remain the learner authority; progress/attempt IDs are retained. UI explicitly labels retirement and requires a reason, with disabled published controls. Course checkpoints and row-version locks reject concurrent stale editor submissions. Neither root publication nor the enrollment-pinned snapshot is mutated by a draft edit.

Acceptance: matching owner bank IDs and reference rejection; path graph validation/private draft and immutable versions; reorder preserves IDs, duplicate/foreign IDs reject, concurrent attempts leave one revision winner; published mutation rejects and archival retains old learner version. Lightweight mocks are source evidence only; PostgreSQL lock/version uniqueness and browser/API/DB pinned-enrollment rehearsal remain pending.

Rollback: hide new workspaces/controls. Keep all published versions and progress; no migration rollback or hard deletion.
