# B10c — Owner draft creation

Owners remain SCHOLARSHIPS, UNIVERSITIES and MAJORS. Create routes are POST at each existing admin owner collection, guarded by the existing owner manage permission. No generic persistence endpoint or import bypass. Creation is an audited atomic owner operation; uniqueness constraints plus existing canonical dedup services reject duplicate identities, including concurrent duplicate attempts. New server IDs are random; users never enter IDs guessed by the server.

Drafts: scholarship publicationStatus=DRAFT using existing createScholarship; university READY_TO_REVIEW/NEEDS_REVIEW; major root/profile READY_TO_REVIEW/NEEDS_REVIEW, version NEEDS_REVIEW and empty review-template sections. No request may set approved/published/status/revision. No public side effects, notification, approval or publication occurs on create. Actor, ADMIN_ENTRY, source URI, reason and source evidence are retained; provenance stays out of public projections. Fields/relationships are completed later using owner editors and canonical pickers. Incomplete records cannot use create as a publication shortcut.

Major requires active canonical DegreeLevel matching BACHELOR/MASTER/DOCTORATE/FELLOWSHIP, active taxonomy, official HTTPS source and SHA256 evidence. Existing dedup service identifies the concept independent of degree; a collision requires linking/owner review, never creates a second concept. Server allocates profile code above catalog floor and persists source/version/sections in the same transaction.

University requires name, HTTPS website/source and source SHA256. Canonical geographic IDs are optional during incomplete draft creation; geography is validated by the existing owner adapter. Existing UniversityDeduplicationService uses source country text, name and website host; a source label is not converted into an ID. Dedup remains the owner's existing policy, not fuzzy matching or automatic merging. Missing geography stays unresolved. Bulk import safety gates remain in force.

DegreeLevel is an independent canonical reference owner with a finite code vocabulary and existing governance API. This package selects an existing active degree, never creates a degree as a side effect of major or scholarship creation. Arbitrary new degree codes or changed approval rules require a separate reference-owner product decision; no additional degree create capability is needed here.

UI: permission-gated create forms on owner lists, clear private-draft wording, bounded canonical pickers, source/reason validation and a link to the returned canonical owner ID. Duplicate errors leave input for review; no auto-retry with a different key. Rollback hides forms, preserving drafts/history. Runtime DB uniqueness/atomic rollback and browser RBAC/public-isolation require isolated rehearsal; source tests do not certify deployment.
