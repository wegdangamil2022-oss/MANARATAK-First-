# B11 — Owner translation capability and source contract

Baseline 8d890cbb. This specification is an expansion checkpoint, not an authorization to bypass INFRASTRUCTURE_ONLY. The approved plan requires owner acceptance, source/version linkage and publication evidence before exposing more editable fields. No global switch is changed, no new store/schema/migration is introduced.

Names above identify field owners, never a name-based relationship. Capabilities are read-only and permission-filtered, independent of whether a generic editor can mutate content. Source supported is distinct from runtime verified. Describe manual workflow honestly rather than inventing a central import path.

Freshness: target owner revision and target translation metadata alone do not prove source freshness. UNIVERSITY source evidence must include canonical owner name/optional source content/source records. MAJOR source evidence must include root identity and the exact profile/version plus section source siblings. The same source digest is checked at transfer and publication; pending evidence retains its reviewed source digest. A changed source cannot publish an old pending candidate even after obtaining a fresh publication approval. Legacy candidates lacking reviewed source evidence require re-review. Transfer replay still uses the existing durable receipt without applying another write or consuming approval twice.

Section target: require profileId AND versionId for version-scoped transfer, assert exact owner/profile/version membership, and select at most one target section. Public projection preserves locale while omitting evidence/private metadata; locale selection occurs on sections from the same published snapshot only. Empty translated values reject; source text is not fabricated or copied to simulate coverage.

Remaining expansion design: add owner-owned description candidates through explicit owner ports for tests/scholarships/courses, with exact immutable version and independent approval payload/receipt linkage; do not widen ORM allowlists. For majors implement published-translation snapshot handover without updating immutable snapshots, and bind root name and translated sections to one profile/version. For university publication persist source evidence in the public reader and enforce stale evidence there. Before enabling any content mode, exercise isolated transaction/approval/publication and legacy-data rehearsal. No speculative migration or guessed policy/IDs.

Rollback: remove capability UI/API and disable affected commands; preserve receipts/history and immutable published snapshots. B11 remains in progress until the remaining owner/public-reader contracts and light acceptance proofs are implemented; no B12 starts before that closure.
