# B05 — قرار البيانات وخطة التوسعة دون افتراض حالة قاعدة البيانات

**SOURCE PLAN ONLY — DATABASE APPLICATION UNKNOWN.** لا اتصال أو قراءة بيانات فعلية في إعداد هذه الخطة.
المرجع: ADR-028، وجرد SQL التاريخي في B04، و[جرد قيود الحوكمة](../reviews/evidence/b05-owner-constraint-inventory-2026-10-15.json).

## قبل أي تطبيق

1. اختيار البيئة المقصودة وأخذ snapshot/نسخة استعادة مثبتة، وتثبيت commit/schema/client المتوافق. لا نسخ اعتماد تشغيل إلى وثائق أو سجلات.
2. تشغيل [فحص القراءة فقط](sql/B05_READ_ONLY_DATA_AUDIT_2026-10-15.sql) بعد التأكد من وجود الجداول، ومطابقة `_prisma_migrations` مع جرد البصمات، والقيود الفعلية بغض النظر عن أسمائها. القيم الحالية **UNKNOWN_NOT_QUERIED**؛ لا تتحول إلى صفر لأن المصدر صالح.
3. تجميد أي ترحيل مطبق/مجهول الحالة: لا تعديل checksum. إذا كان القيد مكافئًا وموجودًا أصلًا في DB خارج السجل، تسوية التاريخ بخطة مالك منفصلة؛ لا إضافة قيد ثانٍ أو إسقاط الأول تخمينًا.
4. إخراج ملخص counts للأيتام/الأكواد غير المطابقة والازدواج وروابط البرامج المخالفة. تحفظ السجلات غير المحسومة كما هي مع سبب ومصدر وموافقة مالك؛ لا ربط بالاسم ولا مسح وثيقة أو snapshot لإجبار validation.
5. وضع حدود زمن/قفل واقعية واستعادة مجرّبة. ترحيل وثائق الطالب يتطلب إيقاف الكتابات المتنافسة أثناء التركيب؛ تشغيل التطبيق بحارس جاهزية جديد قبل تركيب الترحيل سيغلق قدرات الأصول. لا تعطيل readiness لحل عدم التوافق.

## توسعة ISO ودولة الخدمة — مقترح غير مسجل كترحيل

لا تنفذ الأوامر التالية قبل نتائج الخطوات السابقة ومراجعة catalog؛ ليست جزءًا من الترحيل الجديد لوثائق الطالب:

```sql
ALTER TABLE "ReferenceCountry" ADD CONSTRAINT "ReferenceCountry_defaultCurrencyCode_fkey"
  FOREIGN KEY ("defaultCurrencyCode") REFERENCES "ReferenceCurrency"("isoCode")
  ON DELETE RESTRICT ON UPDATE RESTRICT NOT VALID;
ALTER TABLE "ReferenceCountry" ADD CONSTRAINT "ReferenceCountry_defaultLanguageCode_fkey"
  FOREIGN KEY ("defaultLanguageCode") REFERENCES "ReferenceLanguage"("isoCode")
  ON DELETE RESTRICT ON UPDATE RESTRICT NOT VALID;
ALTER TABLE "ServiceProviderRecord" ADD CONSTRAINT "ServiceProviderRecord_countryReferenceId_fkey"
  FOREIGN KEY ("countryReferenceId") REFERENCES "ReferenceCountry"("id")
  ON DELETE RESTRICT ON UPDATE RESTRICT NOT VALID;
```

`NOT VALID` يفرض القيد على الكتابات الجديدة ولا يثبت سلامة الصفوف القديمة. لا UPDATE جماعي ولا تغيير null أو الرموز في هذه المرحلة. بعد تصحيح الأيتام غير الملتبسين بموافقة مالك، نفذ VALIDATE لكل قيد على حدة، وافحص أثر الأقفال والقراءات قبل التحويل. اقتراح ISO/provider يبقى مؤجلًا عن ترحيل الملفات لأن دليل الأيتام وسياسة دورة الحياة غير متاحين.

## rehearsal المطلوب قبل إغلاق DB

- تركيب سلسلة الترحيلات في قاعدة PostgreSQL معزولة مع إصدار Prisma المقصود؛ مطابقة schema/catalog دون قيود مكررة أو إسقاط الحوكمة اليدوية.
- FK03: محاولة تغيير/حذف snapshot أو evidence/decision ترفض؛ حذف المالك/نسخته يرفض RESTRICT، وتظل القراءة والعمل على السجل الجذري المشروع ممكنين.
- البرامج: parent آخر، درجة لا تطابق profile المنشور، جامعة/تخصص مسحوب، نسخة منشورة مفقودة؛ كلها لا تنتج رابطًا عامًا. اختبار تصفح المنح قبل/بعد تغيير النشر مع snapshot محدد.
- ربط ملف الطالب أولًا ثم حذف/تغيير lifecycle في معاملة أخرى: ينتظر قفل الأصل ثم يرفض بعد commit الربط. عكس الترتيب: ينتظر الإرفاق ثم يرفض عندما لم يعد الأصل ACTIVE. rollback للطرف الأول لا يترك ربطًا/حذفًا جزئيًا.
- وجود binding منتهٍ أو بلا موافقة مراجعة لا يسمح بتجاهله: تنظفه سياسة المالك الفعلية أو unlink ناجح؛ بعدها يبقى احتفاظ الأصل وlegal hold والحراس الأخرى مطبقة. جرّب إعادة الإرفاق والحذف بعد التنظيف.
- تحقق غياب/تعطيل trigger أو replication role غير origin يجعل readiness يفشل، ولا يجيز حذفًا تعويضيًا. احفظ نتائج التزامن وقيود catalog وبصمات المصدر مع commit.

## التراجع

قبل التطبيق يبقى التغيير source-only. بعده يُوقف مسار الربط/الحذف المتأثر عند عطل؛ تبقى الأعمدة القديمة والدليل والقيود والحراس السليمة، دون DROP أو cascade أو إعادة فتح حذف غير محمي. لا تُحذف بيانات لتسهيل rollback. إعادة عميل سابق تستلزم المحافظة على عقد ownerId/degree/publication وreadiness المتوافق؛ لا إسقاط قيد الإرفاق كحل سريع.

**ما نُفذ:** تصميم، كود المصدر، SQL جديد غير مطبق، فحوصات ببدائل وتحليل ملفات. **ما لم ينفذ:** أي أمر من الفحص read-only على بيئة فعلية، أو تطبيق/validation/rehearsal أو استعادة أو نشر.
