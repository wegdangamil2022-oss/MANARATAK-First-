## الإصلاح الوظيفي

كشف اختبار PostgreSQL 16.15 بعمليتي HTTP مستقلتين سباق تجديد حقيقيًا: قرأت المعاملتان الرمز الأب، وأكملت الأولى التدوير، ثم فشلت الثانية بـ`P2034`. أعادت واجهة المصادقة 401، لكن سليل الأولى بقي نشطًا لأن إلغاء العائلة داخل المعاملة الملغاة لم يُحفظ. هذه فجوة إلغاء جلسات؛ ليست مجرد رسالة خطأ.

أُصلح `PrismaSessionManager.consumeAndRotateRefreshSession` بإعادة المعاملة ذات العزل Serializable عند `P2034` فقط، بحد أقصى ثلاث محاولات. القراءة الجديدة تلاحظ التدوير المحفوظ وتلغي العائلة. لا تُعاد أخطاء الاتصال أو النتائج مجهولة الحفظ، ولا يُعاد إصدار رمز بوصفه ناجحًا بعد الفشل. يبقى الاستنفاد أو تعطل القاعدة فشلًا، ولا يوجد ضمان استمرار الخدمة خلال عطل مستمر. السلوك متوافق مع [عقد معاملات Prisma](https://www.prisma.io/docs/orm/v6/prisma-client/queries/transactions).

ثبت الفشل قبل الإصلاح: [المصدر 6306661](../reviews/evidence/post28/630666154a7a0594fc7b2530565ab1fa4012f055/r08-fault-recovery/evidence-index.json). ثم نجحت الحالات الخمس كاملة على [5c5152f](../reviews/evidence/post28/5c5152ff2c575414b0e04f7b450330b61cef2070/r08-fault-recovery/evidence-index.json): الدخول والتجديد والخروج بين العمليتين، إعادة استخدام الأب، التعليق، CSRF/origin، والسباق المحدد. تُظهر [لقطة الأثر](../reviews/evidence/post28/5c5152ff2c575414b0e04f7b450330b61cef2070/r08-fault-recovery/effect-snapshot.json) أن جلستي الحالة المتزامنة ملغيتان، دون حفظ الرموز أو بصماتها في التقرير.

المصالحة انتظرت موعدها الفعلي البالغ دقيقتين؛ لم تُعدّل تواريخ الاستحقاق أو lease لإجبار النجاح. الخادم الصناعي استُعمل عبر TCP و`fetch` الحقيقيين مع adapter المالية الفعلي وPostgreSQL، دون mock لنتيجة الدفع. `runtimeApproved` في هذا الاختبار يخص المتجر الصناعي على loopback فقط، ولا يوثق اعتماد مزود إنتاج. إثبات webhook يختبر verifier ومخزن replay الفعليين؛ لا يحول الإشعار وحده فاتورة إلى مدفوعة ولا يدعي endpoint ماليًا موصولًا.

التجربة الأولى للجلسات توقفت في hook قبل تنفيذ أي حالة؛ محفوظة على [619b191](../reviews/evidence/post28/619b191afb50fc4e699f5175c39eb1e373cbd61e/r08-fault-recovery/evidence-index.json)، ولا تُحسب مرورًا أو إثبات عيب. أُضيف reporter نصي إلى جانب JSON لإظهار أسباب الفشل. فشل أول غلاف لحدث الهوية الصناعي لأن metadata/aggregate لم يطابقا عقد `PrismaIdentityRepository`؛ صُحح الغلاف وأُعيدت الحالة الفاشلة وحدها، دون إضعاف حارس المصدر أو إعادة الحالة الناجحة. لم تُعد الحالات الخمس السابقة لاستيراد الدورات؛ الحد الأدنى صار ستًا لوجود الحالة الجديدة، وليس ادعاء 6/6 جديدًا.

## العزل والفحوص

جميع قواعد هذه الدفعة أُنشئت من الصفر في clusters PostgreSQL 16.15 مستقلة على loopback، ببيانات صناعية ودور التطبيق `post28_app`. استُخدم migrator منفصل للتجهيز فقط؛ لا DDL أو صلاحية تحديث migration ledger لاختبارات التطبيق. أضاف `--r08-provider-fixtures` صلاحية DML على `FinancePaymentAttemptRecord` في المختبر الجديد فقط؛ لم تتسع المنح الافتراضية. لا schema أو migration جديدة أو تغيير لهجرة تاريخية. أُوقفت المختبرات كلها. أُعيد فتح ثلاثة منها لالتقاط الآثار داخل معاملات READ ONLY بدور التطبيق، ثم أُوقفت مجددًا بإيصالات مستقلة؛ لم تُمس قواعد أخرى.

نجح 19 اختبار وحدة في الملفين المتأثرين `PrismaSessionManager` و`AuthService`، بينها ثلاث حالات جديدة للتعارض وحد المحاولات ورفض إعادة الخطأ غير المؤكد. نجح فحص أنواع infrastructure. نجح ESLint للملفات المتغيرة بلا أخطاء، مع تحذير `any` موروث واحد في اختبار الجلسات. نجح 36 اختبار تجهيز للصلاحيات، ثم أُعيد عقد course receipt وحده بعد رفع حد الاكتشاف للحالة الجديدة. لم يُعد build أو اختبار متصفح محلي أو مجموعات R05/R06.

كشف CI الأول على `a3c0dde` تقادم مراجع جرد البيئة بعد إضافة الملفات. السجل الفعلي يؤكد السبب؛ جُددت المراجع وبقي العدد 320 اسمًا دون قراءة قيم الأسرار. نجح فحص الجرد والتنظيم محليًا. اكتمل تشغيل المصدر المصحح [39326541345](https://github.com/wegdangamil2022-oss/MANARATAK-First-/actions/runs/39326541345) بنجاح في المهام الست، ومنها جميع فحوص المصدر والأنواع والبناء والوحدة، واسترجاع الحزم والتشغيل الفعلي للصورة وAPI/Web/Admin على Linux مع PostgreSQL وHTTPS والمتصفح. نجحت check runs الثلاثة والعشرون، بما فيها CodeQL، دون فشل أو انتظار. [إيصالات المصدر وRedis والمتصفح وCI](../reviews/evidence/post28/4f9573332afe83ed2aa804f36494b520c574fe6d/r08-current-ci/evidence-index.json) محفوظة مع بصمات ZIP المتحققة من GitHub. أُوقف API بالرمز صفر في 117ms، وأُزيلت الحاويات والشبكة المملوكة. هذه الاختبارات التشغيلية لا تُعاد بسبب commit التوثيق اللاحق.

## ما بقي للقبول الشامل

| المتبقي | الأثر والحد الحالي | ما يلزم |
|---|---|---|
| جمع API المبني والجلسات الموزعة وTLS وRedis في topology واحدة | أدلة HTTPS المبنية لـR07، وجلسات HTTP المجمعة، وRedis بين عمليتين صحيحة لكنها منفصلة؛ لا تمنع التطوير المحلي، وتمنع قبول هذا السيناريو للنشر | مختبر تكامل لتلك المكونات وقياس المحدد عبر مساري API الحقيقيين؛ لا يكفي عداد Redis منفصل |
| بوابات staging/production للملفات والبريد | إعداد test يستعمل local/captured؛ إعداد staging يرفض مزودات غير معتمدة. `createRateLimiterForRuntime` يختار المحدد المحلي خارج production/staging؛ لا يصح تسميته موزعًا لمجرد تمرير REDIS_URL | مزودات/عقود معتمدة وإعدادات نشر قابلة للتحقق؛ لا تخفيف الحراس أو تقديم sink تطوير كاعتماد إنتاج |
| بقية مصفوفة faults للمزودين | التحصيل الصناعي ودليل المتجر وwebhook ليست تغطية شاملة للاسترداد والتحويل البنكي وFX والملفات والبريد وAI، أو suppression/privacy/quota | تنفيذ الحالات المعنية بمزودات صناعية أو sandbox مفوض فقط، مع آثار كل سلسلة؛ لا تفعيل مزود مؤثر افتراضيًا |
| DLQ والتنبيه التشغيلي وربط abort بالأثر | الاستنفاد الحالي يركن Outbox بموعد year9999؛ دليل الإيقاف والمهلة لا يثبت وحده تنبيهًا خارجيًا أو إلغاء كل أثر مالك متأخر | ربط إشارات التشغيل الحالية بمراقبة معتمدة وإثبات المعالج المتأخر دون أثر مكرر |
| تجميع أدلة القبول لنفس مرشح الإصدار | هذه دفعة إصلاحات بأدلة مصادر دقيقة ومتعددة، وليست قبولًا رسميًا شاملًا على SHA واحد | جولة قبول مستهدفة للمتطلبات المفتوحة بعد جاهزية topology؛ إعادة ما تأثر فقط |

لم يُفعّل عامل canonical عام: يبقى `ImportHandoffDispatcher` مقصورًا على SCREENING_ONLY، ويستمر رفض المستهلك الذي يكتب إلى المالك دون إيصال ذري. إثبات العملية الجديدة يستعمل مسار المالك المراجع الموجود ويحفظ الدورة IMPORTED غير منشورة. لا SMTP أو دفع أو بريد أو AI خارجي، ولا Neon أو إنتاج أو دمج main أو نشر. حالة R05 وإغلاق R06 الأساسي واستثناءاتهما محفوظة. نقطة الاستئناف: نتائج CI للمرشح المرفوع، ثم تكامل الجلسات الموزعة مع topology المعتمدة وبقية حالات المزودين.
