## Completed source changes

1. **Identity and sponsors:** Retain existing canonical Scholarship `publicId` and deduplication identity, owner-unique source keys and conditional identity collision checks. The sponsor context remains P12-owned, and may now reference a canonical P11 University via `sponsorUniversityId`; the admin relationship editor selects the University owner, and import transfer can resolve an existing sponsor's University identity. No University or sponsor identity is cloned into another upstream domain.
2. **Canonical references:** Scholarship owner canonical authoring validates P7 country/currency/language, academic degree, P10 Major, P9 InternationalTest, P11 University and AcademicProgram identities. Exact canonical references are mandatory; candidate-list first-item fallback was removed. Program must belong to its selected University, and a program without University fails validation. Sponsor reference and target relationships are separate.
3. **Eligibility, funding, documents:** Existing structured benefit, degree, major, nationality/country, score-range, test, required-document and program relations remain owner-operated. Validate nonnegative finite funding amounts, linked P7 currency for amounts, finite nonnegative eligibility thresholds, proper min/max ranges and unique relationship source keys. Multiple eligibility items and application-cycle/version ownership remain in the canonical model.
4. **Source identity and import reviews:** Existing Phase 6 handoff and P12 import review/lease/atomic transfer contracts remain. Child collections use stable unique `scholarshipId + sourceKey` upserts rather than wholesale delete/recreate (including evidence and links). New conflicting supplier/import content does not silently overwrite populated scalar data or reviewed child collections; require explicit reconciliation. Source evidence remains traceable and import transfers never auto-publish.
5. **Atomic administration and concurrency:** Added source-only monotonic `Scholarship.revision` column plus unapplied migration. Every scholarship authoring/lifecycle command must include authenticated actor, review reason and (except create) a caller `If-Match` revision. P12 use cases fail closed unless auditable transactional mutation/outbox infrastructure is available. The Prisma owner is row-locked, expected revision is compared, and revision advances within the audited transaction. API responds 428 for missing precondition and 409 for stale revisions, returns ETag/X-Entity-Revision; admin client tracks and supplies revision, clears on auth changes, bypasses stale scholarship GET cache.
6. **Lifecycle, publication, public projection:** Published/archived/rejected data is not editable through generic owner updates. Structural edits invalidate READY_TO_PUBLISH status. Publication requires verified and complete owner, version/cycle/sponsor context, resolved links and official HTTPS provenance. Referenced Majors/Universities and sponsor University must be published and linked academic programs active; public queries require published owner/version with verified source. Explicit public allowlist excludes raw optionalFields, source evidence, owner IDs, internal workflow/revision, audit metadata and draft data. Returned public major/university links also require publisher status; unpublished cross-domain references remain internal.
7. **New Majors boundary:** Scholarship-origin labels stay scholarship-owned source rows, and unresolved majors are visible via Section 09 New Majors review; reviewed approval/linking is handled only by the P10 owner. Changed scholarship-to-major resolution writer to disallow modifying published/archived/rejected Scholarships. No inline canonical Major creation or automatic approval was added.
8. **Admin screens:** Existing catalog detail, alternative detail, canonical relationship editor and client now submit review reason/conditional revision for create/update/state changes and support sponsor University/major-review navigation. Existing API route retains the `admin:scholarships:manage` RBAC middleware.
