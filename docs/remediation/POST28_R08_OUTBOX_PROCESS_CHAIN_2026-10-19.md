# R08 — سلسلة Outbox فعلية مع التعطل وإعادة التسليم

بدأ التنفيذ التشخيصي المستقل لـR08 حسب توجيه المالك. **أُثبت نطاق سلسلة العامل إلى مساحة الطالب؛ القبول الشامل لـR08 مفتوح.** لم يُرقَّ مرشح R07 أو تُتجاوز بوابات إصداره.

## ما يعمل بالفعل

شغّل الملف `tests/database/fixtures/post28-r08-outbox-worker.mjs` عمليات Node مستقلة، بدور `post28_app` على PostgreSQL 16.15 جديد ومعزول. المسار الفعلي هو Dispatcher ثم Prisma Outbox Store ثم StudentWorkspaceOutboxDeliveryGateway ثم StudentWorkspaceUseCases وPrismaStudentWorkspaceRepository. التخزين الفعلي يشمل Inbox ومساحة الطالب وAudit. لم تُستبدل المستودعات بذاكرة أو mocks.

الـfixtures تنشئ هوية ودورًا وتعيينًا وحدث `RoleAssignmentCreated` صناعيًا بصيغة العقد الصحيح؛ لا تُقدَّم هذه التجربة كإثبات أن أمر المالك الذي يُصدر الحدث نُفذ أيضًا. التوقف المحقون قبل/بعد استدعاء بوابة الإسقاط لا يغير خوارزمية claim أو heartbeat أو commit. لا مزود خارجي أو دفع أو بريد.

| الحالة | النتيجة المثبتة |
|---|---|
| عمليتان مع lease حي | الثانية لم تأخذ الحدث؛ الأولى أكملته وأنشأت مساحة ACTIVE وإيصالَي الحدث الأصلي والتفعيل |
| قتل قبل الأثر | لا Inbox محفوظ؛ بعد انقضاء lease الطبيعي أخذته عملية جديدة وأكملت الإسقاط |
| قتل بعد الأثر وقبل ack | Inbox ومساحة الطالب محفوظان؛ إعادة التسليم أكملت Outbox دون تغييرهما أو تكرار Audit |
| فشل حتى استنفاد المحاولات | attempts=2، لا مساحة أو Inbox؛ توقف الالتقاط باستخدام آلية FAILED وموعد year9999 الحالية |

انتُظر انتهاء lease الحقيقي بعد خروج العملية؛ لم تُكتب تواريخ منتهية يدويًا. الاستنفاد هنا يثبت آلية ركن العمل الموجودة، وليس DLQ مستقلًا أو تنبيهًا تشغيليًا. لا ادعاء exactly-once transport أو أثر مالي مختبر.

## التغييرات والفحوص

أضيف profile باسم `r08-outbox-chain` بحد أدنى أربع حالات، وتحقق اكتشاف الحالات والنتائج عبر runner الرسمي. ظل فحص الهدف والأدوار والمصدر النظيف قائمًا. أضيف خيار `--r08-outbox-fixtures` إلى تجهيز **قاعدة جديدة فارغة فقط**، يمنح DML على `StudentWorkspaceEventInbox` لدور التطبيق. لم تتسع قائمة المنح الافتراضية؛ لا صلاحيات DDL أو قراءة ledger للتطبيق، ولا تغيير schema أو migrations.

المحاولة الأولى على `f374d55` فشلت 0/4 بسبب نقص منحة Inbox في المختبر؛ أدى بقاء الحدث غير المنجز إلى تأثر الحالات اللاحقة. قرئت `lastErrorText` بدور التطبيق لتحديد `42501` قبل إعادة التشغيل. هذا نقص تجهيز اختبار، وليس عيبًا مثبتًا في صلاحيات الإنتاج. أُوقفت القاعدة واحتُفظ بدليل الفشل.

بعد الإصلاح على `865dfac48534fbb8b8e643344e1261b183d35e31` نجحت 4/4، بلا تخطٍّ. أثناء المراجعة وُجد أن مقارنة Audit تستعمل studentReferenceId بدل workspace.id؛ قُويت لتشترط وجود سجلات فعلية. أُعيدت **حالة AFTER_EFFECT وحدها** على `770d787c172d1ce826c7bb15ddeecb90ecc957d5` في مختبر جديد، فنجحت 1/1؛ الحالات الثلاث غير المختارة مسجلة في التقرير الخام، ولا تُحسب مرورًا جديدًا على المصدر الأخير.

نجح 36 اختبارًا لتجهيز الصلاحيات المتأثر، وأربعة لعقد الاختيار الدقيق، وESLint للملفات الخمسة المتغيرة. لا إعادة build أو browser أو مجموعات R05/R06 العامة. أُوقفت المختبرات الثلاثة، ولم تُحذف قواعد سابقة أو تُمس Neon. ملفات حالة المختبر الأولية تسجل الإنشاء؛ ملف cleanup المنفصل هو إثبات الإيقاف النهائي.

## المتبقي ونقطة الاستئناف

1. SIGTERM على Linux فعلي: منع claim جديد، drain للمهام، وإغلاق الموارد ضمن 15 ثانية وحالة تجاوز محدودة. Windows process kill في هذه الدفعة لا يثبت SIGTERM.
2. جلستان/عمليتا API مع rate limiting موزع وRedis namespace/outage/freshness، وreadiness يرفض عاملًا متوقفًا.
3. ترتيب أحداث المالك المتأخرة والتعارضات مع الحالة الحالية، وسلسلة الاستيراد إلى تطبيق المالك بدل نطاق screening السابق فقط.
4. provider stubs لطلبات timeout/unknown outcome وwebhook موقّع وreplay/reconciliation؛ لا مزود مؤثر دون تفويض.
5. استكمال إيصالات وأرصدة السلاسل المالية المعنية عند اختبارها؛ نتائج الطالب هنا لا تثبت منع تكرار المال.

نقطة الاستئناف التالية: slice إيقاف العامل وملاحظة freshness، مع الاستفادة من اختبارات lifecycle السابقة دون تكرارها بلا تغيير. R05 تبقى PASS_LOCAL_ONLY؛ R06 نطاقها الأساسي مكتمل باستثناءاته وقبولها الشامل مفتوح؛ R07 بوابات الإصدار مفتوحة. لا نشر أو دمج main. يُحفظ commit التوثيق بـ`[skip ci]` لتجنب إنشاء تشغيل عام آخر أثناء بقاء مرشح R07 السابق؛ لا يُدَّعى نجاح CI على مصدر R08.
