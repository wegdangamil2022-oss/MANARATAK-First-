# الموظفون والهويات والأدوار والصلاحيات — التنفيذ وحالة التفعيل

هذا التسليم ينفذ ترتيب الوظائف الحالية والحواجز الأمنية ذات الأولوية، ويجهز تخزين مسودات Staff والهيكل الوظيفي كمقترح مستقل. **لا يعني اكتمال رحلة التوظيف والدعوة والتفعيل والمغادرة بالكامل.**

## المنفذ

- أربعة مداخل للموظفين: الموظفون، الدعوات والانضمام، الهيكل الوظيفي، التغييرات والمغادرة. دليل الهويات العام يبقى أداة منفصلة داخل المدخل الأول، ولا يحوّل كل Human أو حامل دور إلى موظف.
- خمسة مداخل للصلاحيات: الأدوار والقوالب، تعيينات الوصول، الصلاحيات والسياسات، التحقق والمراجعات، الحوكمة والأمان. إنشاء الدور عند الطلب، مع روابط التبويبات القديمة وتفاصيل الهوية والرجوع بفلاتر الدليل.
- عناوين مدمجة وخط Cairo صريح، اختيار نيلي وأيقونات ذهبية، وبترولي ظاهر في الأزرار. التصنيف الأكاديمي والمالية وخدمات المؤسسات تغيرت ألوان رؤوسها وأزرارها الثانوية فقط؛ ترتيبها محفوظ.
- تغيير الدور أو الإسناد الحساس والسياسات والوصول الطارئ يحتاج موافقة محفوظة يصدرها المعتمد من حسابه. صاحب الطلب ينفذ النسخة المعتمدة لاحقًا. انتهاء الموافقة أو استهلاكها أو تغير الدور أو السياسة أو الهوية يبطل التنفيذ.
- استهلاك الموافقة وفحص النسخة يتمان داخل معاملة الكتابة نفسها مع سجل التدقيق وoutbox. سحب إسناد معتمد يظل ممكنًا من هوية غير نشطة، بشرط تطابق حالتها والنسخة المعتمدتين. إعادة إنشاء الإسناد تبطل موافقة سحبه القديمة.
- التفويض يحتفظ بقيود دور المانح؛ الوصول الطارئ وحده لا يسمح بمنح وصول دائم. تعديل سياسة مستخدمة يتطلب سلطات أصلية غير مقيدة لتلك الصلاحيات لدى المانح، إضافة إلى الاعتماد المستقل.
- مسار الاتصال الإداري يرفض أعلام التوثيق اليدوي للبريد والهاتف. مسار إثبات الملكية يبقى لدى Identity؛ لم نغير حسابًا أو نتجاوز MFA.
- فحص الوصول يعلن وقت الفحص وسياق اتصال المسؤول، ولا يدعي جاهزية جلسة الموظف أو اكتمال MFA فيها.

## Staff: مصدر جاهز للمراجعة وتفعيل مشروط

يوجد مالك مستقل لمسودة العضوية الوظيفية والأقسام والمسميات وأحداث المسودات. الحفظ لا ينشئ Identity ولا يمنح Role ولا يفعل العضوية. الربط بهوية موجودة لا يعد إثبات ملكية أو قبول دعوة.

المصدر يطبق المعاملة المدققة، التحقق من تطابق المسمى والقسم، منع دورات الأقسام وإدارة الذات، نسخ التعديلات، وإلغاء المسودة فقط. لا توجد واجهة حذف سجل موظف أو تعطيل حساب طالب باسم المغادرة. يستخدم هذا النطاق حاليًا إذن **admin:identities:manage** مع مصادقة الإدارة وMFA؛ لا توجد صلاحية مفترضة أو منح تلقائي.

مقترح المخطط: [staff-draft-organization-20261028.sql](proposals/staff-draft-organization-20261028.sql). يحتوي أربعة جداول جديدة وقيود المصدر والتواريخ وعضوية مفتوحة واحدة لكل هوية، وفهارس ومنح محدودة لدور التطبيق القائم. لا يتضمن ترحيل بيانات الهويات أو الأدوار أو تغييرها. المخطط لم يطبق على القاعدة الأصلية.

قبل قراءة الدليل تفحص الواجهة وجود الجداول وصلاحيات دور القاعدة. غياب التهيئة يعرض حاجزًا صريحًا؛ ليس عداد صفر أو نجاح حفظ وهمي. أعطال الاتصال تختلف عن غياب السجلات.

## ما لا يفعله هذا التسليم

- لا يرسل دعوات، ولا ينشئ رمز قبول أو رابطًا سريًا داخل Notification/outbox، ولا يفعل مزود إرسال خارجي.
- لا يفعل Staff، ولا ينقل الموظف أو ينهي عمله، ولا يخمن مصدر الإسنادات القديمة.
- لا ينشئ بعد سجل مصادر استحقاق الدور أو الانتهاء أو حاجز منع الإدارة المستقل. يلزم استكمال هذه العقود واختبارها قبل تفعيل الدعوات والمغادرة، مع إثبات بقاء حساب الطالب وحماية آخر مسؤول استرداد.
- تطبيق مقترح جداول المسودات وحده **لا** يفتح الدعوات أو التفعيل أو المغادرة؛ قدرات هذه العمليات تبقى false في الخادم.

## التحقق وحدوده

نجح 167 اختبارًا في 31 ملفًا، مع TypeScript وبناء لوحة الإدارة وفحص ESLint دون أخطاء. توجد تحذيرات في الفحص، ولم يُجر فحص CI الشامل أو قبول القاعدة الأصلية بالكتابة.

اختبارات القبول المعزولة تغطي رفض الموافقة المدعاة والمنتهية والمستهلكة، تغير النسخ، الاستهلاك ضمن معاملة الكتابة وفشل التدقيق، قيود التفويض، إثبات ملكية الاتصال، غياب المخطط والصلاحيات، منع حقن منح أدوار في المسودة، بنية الملاحة باللغتين، وتفاعل صندوق الموافقات. الأدلة التشغيلية المحلية تسجل SHA الملفات المقدمة وتطابق أصول البناء وحدود المصادقة.

لم تطبق ترحيلات أو تعبئة أو حذف أو تجارب قبول على القاعدة الأصلية، ولم تجر معاينة بالصور أو ادعاء تحقق بصري مصادق. ليس هذا قبولًا تشغيليًا كاملًا لسيناريوهات الخطة الـ120 أو لاختبارات تزامن PostgreSQL.
