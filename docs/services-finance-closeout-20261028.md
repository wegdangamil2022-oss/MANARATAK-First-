## ما أُغلق

- تنظيم الخدمات بثلاثة مداخل والعمليات بأربع مجموعات؛ تنظيم المالية بسبع مجموعات مع استمرار الروابط السابقة.
- حفظ الصلاحيات ونطاق الموظف والبيانات الشخصية، وفصل عرض الطلب عن إدارة الكتالوج.
- محرر الخدمة وتفاصيل الطلب، مع خط القاهرة والنيلي والذهبي المعتمدين.
- البحث عن مراجع التشغيل من الخادم قبل تقسيم النتائج إلى صفحات؛ لم يعد البحث محصورًا في أول 20 سجلًا. نتائج البحث وعددها يحتفظان بنفس نطاق الصلاحية؛ لا يُبحث داخل بيانات الطالب أو محتويات الطلب.
- توسيع قائمة حقول الخدمة يحفظ أنواع الحقول الموجودة وحساسيتها وإلزاميتها؛ الحقل الجديد النصي لا يعيد تعريف بقية الحقول.
- عملية إنشاء الفاتورة تحتفظ بقفل التنفيذ أثناء قراءة السعر المعتمد. الإرسال المكرر أثناء القراءة لا ينشئ طلب فاتورة آخر؛ فشل قراءة السعر يمنع إنشاء الفاتورة ويتيح إعادة المحاولة.
- مرجع خصم بلا حالة لا يعرض حالة ACTIVE مصطنعة.
- سجل المالية يقرأ القيود الحالية مع فصل العملات والتحقق من الاتزان؛ لم يُضف مسار لترحيل قبض أو مصروف وهمي.

## دليل الاختبارات وحدوده

نجح **200 اختبار في 29 ملفًا**، يشمل اختبارات التطبيق وواجهات API والمكونات ومستودعات القراءة المعزولة:

| الموضوع | الدليل |
| --- | --- |
| خدمة مجانية | لا يطلب مسار FREE فاتورة دفع غير لازمة |
| خدمة مدفوعة | يمنع التنفيذ دون تصفية مالية من المالك المالي |
| ربط الفاتورة | حفظ النية قبل الربط وإعادة المحاولة بنفس النية دون تغيير السعر التاريخي |
| العبث بالسعر | رفض المبلغ المختلف عن السعر المعتمد |
| فصل الصلاحيات | منع كشف بيانات الطلب أو تعديله خارج النطاق؛ بقاء حماية المستندات وMFA |
| بحث التشغيل | البحث يسبق pagination، وتحتفظ القوائم الحساسة بنطاق الموظف |
| محرر الخدمة | إضافة حقل لا تمحو نوع الحقل السابق أو بيانات اللغات وSLA |
| تكرار زر الفاتورة | قراءة سعر واحدة وطلب إنشاء واحد أثناء الإرسال المتزامن؛ لا كتابة بعد فشل القراءة |
| السجل المالي | دقة BigInt، وفصل العملات، ورفض القيد غير المتوازن أو البيانات التالفة |

نجح فحص TypeScript والبناء وESLint دون أخطاء مانعة. بقيت تحذيرات التنسيق/الأنواع الموجودة في الملفات وتحذير حجم حزمة الإدارة؛ لا تمثل اختبارات قاعدة حقيقية أو اعتمادًا محاسبيًا.

لم تُشغّل صور أو لقطات شاشة في جولة الإغلاق بناءً على طلب المستخدم. الاختبارات المذكورة تستعمل بدائل معزولة، ولا تثبت وحدها سلامة سباقات المعاملات على قاعدة حقيقية. فحص التشغيل الأصلي يثبت هوية البيئة وملفات الإصدار واستجابة HTTP وحماية API؛ قبول الرحلة داخل جلسة مسجّلة الدخول ما زال NOT_VERIFIED.

## خارج الإغلاق: قدرات غير مفعّلة

سندات القبض اليدوي، ومستندات المصروفات وفواتير الموردين، والصناديق والحسابات البنكية الفعلية، وتعديلات الطلب والاسترداد على مستوى بنود الخدمة تبقى **OPEN / NOT_ENABLED**. يلزمها تصميم مخطط مستقل واختبارات قاعدة معزولة واعتماد الكيان والعملة والسياسات والفترات والموافقات قبل التشغيل المالي الحقيقي. لم تُستبدل بقيود تسوية عامة أو شارات دفع يدوية.

هذه المتطلبات موثقة لمرحلة مستقلة، ولا تمنع الانتقال إلى قسم إداري آخر. لا يُعلن اكتمال الخطة المحاسبية كاملة، ولا تُعرض أرصدة بنك أو أرباح غير مثبتة.
