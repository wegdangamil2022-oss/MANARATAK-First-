# القسم 03 — تنفيذ إدارة المنح

المرجع: `SCHOLARSHIP_ADMIN_APPROVED_SPEC_2026-10-25.md`، نسخة كاملة من القسم المعتمد في الملف المرفق. تحقق `git ls-remote` أن أحدث main عند البدء هو `10179ab97eddba9b236238714dea1d68859f469e`. ملفات المنح المستهدفة لم تختلف عن main قبل العمل. الفرع `feat/scholarship-admin-20261025` مبني فوق `feat/review-workspace-20261024` لحفظ إصلاحات الإدارة السابقة؛ لم يُدمج في main.

## المنجز برمجيًا

- إعادة تنظيم تفاصيل القالب التسعة إلى تبويبات أفقية 5/3/2 أعمدة، عرض كامل، Cairo، عنوان 22px، رأس نيلي/بترولي ومحتوى قراءة افتراضي. بقيت حقول التحرير الأصلية وعقود العلاقات محفوظة.
- عرض قيم الصفر، المبالغ بوحداتها الصغرى دون تحويل نقدي مفترض، ومصادر الإعلان والتقديم وموقع الجهة كل على حدة. الروابط لا تستعمل `#` ولا تقبل بروتوكولات تنفيذية أو بيانات دخول مضمنة.
- مكان واحد لحفظ البيانات وسببها، مع سبب مستقل لقرارات الحالة. حفظ العلاقات منفصل؛ يبقى المحرر مركبًا عند تبديل التبويبات حتى لا تضيع مسودته. تُعطل قرارات الحالة عند وجود تغييرات معلقة.
- تحذير إغلاق/تحديث المتصفح وروابط المغادرة، وحوار حفظ/متابعة/تجاهل عند إلغاء التحرير. التنقل بين التبويبات يحفظ القيم. إلغاء النشر والأرشفة لا يغيّران عقد المالك.
- API الواجهة يرسل If-Match بالإصدار المحمل لجميع تحديثات المنحة وأوامر الحالة وترجمة وصف المنحة. لا تُرسل كتابة عند غياب إصدار صالح. الحراسة الخلفية كانت موجودة أصلًا؛ لم يُنشأ بروتوكول إصدار بديل.
- `publicationReadiness` ناتج من فحص الجاهزية الفعلي للمالك، بما يشمل المرجع ونسخة المحتوى ومصدره والعلاقات. إذا تعذر التحقق فلا يُمكّن النشر. تظل صلاحيات الخادم والتحقق وقت التنفيذ المرجع النهائي.
- عدّادا `inReview` و`incomplete` يأتيان من COUNT مطابق تمامًا لـ READY_TO_REVIEW وINCOMPLETE؛ أبقيت المؤشرات القديمة لمستهلكيها. لا جمع للنواقص والترجمة. عداد نتائج الصفحة يصف الصفحة وإجمالي طلب البحث دون ادعاء اعتماد جميع السجلات.
- تعريب تسميات محرر العلاقات بالاستفادة من مزود اللغة الحالي، دون تغيير DTO أو معرفات العلاقات. إزالة ادعاء التمويل 100% والنص الثابت الذي كان يدعي مجانية تقديم جميع المنح.

## دليل التحقق الحالي

- 49/49 اختبارًا في مجموعة المنح: عقد If-Match، منع الكتابة بلا إصدار، تطابق فلاتر العدادات، عقود المالك الحالية، تسعة تبويبات، قراءة أولًا، حفظ واحد، الاحتفاظ بالمسودة عبر التبويبات، سبب الحفظ، الصفر، وسلامة الروابط.
- TypeScript للـadmin وAPI ناجح. ESLint للصفحات والمكونات المستهدفة ناجح بلا تحذيرات. بناء admin الإنتاجي ناجح مع تحذير حجم الحزمة المشتركة القائم.
- متصفح حقيقي عند 1440×1000 و390×844: تسعة تبويبات، عنوان 22px، Cairo، دون تجاوز عرض الصفحة؛ RTL وLTR. الصور داخل `evidence/scholarships-20261025` من معاينة معزولة ببيانات صناعية وبدائل لعقود الشبكة والمصادقة. لا تثبت هذه الصور E2E على قاعدة بيانات.
- لم تُكتب بيانات صناعية أو تغييرات على القاعدة الأصلية، ولم تُشغّل ترحيلات أو يُستبدل خادم الإدارة الحالي. تحسين سرعة القاعدة مؤجل حسب المستخدم.

## بنود لم تغلق بعد

1. اختبار E2E كامل بقاعدة PostgreSQL معزولة لحفظ المحتوى والعلاقات والترجمة، وحالات النشر، وسباق موظفين، وإثبات تطابق العدادات على صفوف متداخلة فعلية. الاختبارات الحالية للعقد والمستودع تعتمد بدائل اختبار وليست هذا الإثبات.
2. استكمال ترجمة نصوص نماذج التحرير القديمة كلها ونافذة الصحة والتدقيق؛ وضع القراءة والتنقل الجديد ومحرر العلاقات معرّبة، لكن لا ندعي اكتمال جميع نصوص الصفحة بالإنجليزية.
3. اختبار التنقل بزر رجوع المتصفح بين سجلات مع مسودة غير محفوظة؛ لا يُعد beforeunload وحده دليلًا على تغطية انتقالات SPA في سجل المتصفح.
4. فحص 360/768/1280 وتكبير المتصفح 200% وقارئ الشاشة وحوار التأكيد والتركيز. الصور الحالية لا تثبت هذه البنود.
5. رابط الصفحة العامة مشروط بإثبات العرض العام للسجل، وليس بمجرد وجود slug؛ لم يُضف رابط غير مثبت. ربط النواقص بحقولها، وأزرار إلغاء تحرير العلاقات، وإثبات إعادة قراءة الحفظ ما زالت تحتاج فحص قبول تكاملي.

هذه حالة تنفيذ فعلية قابلة للمراجعة، وليست إعلان إغلاق القسم 03. لا نشر إنتاج أو دمج تلقائي.
