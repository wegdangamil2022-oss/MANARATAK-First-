# B10b — إدارة الحرم والوحدات

الحالة SOURCE_VERIFIED؛ runtime/database PENDING؛ deployment NOT_PERFORMED. بدأت بعد توثيق ودفع B10a في 648e0433. [المواصفة](../remediation/specs/B10b_UNIVERSITY_STRUCTURE_CONTRACT_2026-10-15.md) تثبت المالك ودورة الأرشفة وRBAC والأثر العام قبل الواجهة.

أثبت الجرد وجود تأليف الحرم والوحدات أصلًا في UniversitySectionsEditor وPUT normalized-details داخل مالك الجامعة؛ لم نبن CRUD موازيًا. أُكملت إعادة تحميل campusId وparentOrganizationUnitId إلى اختيار المالك نفسه، مع الحفاظ على ID، وإرسال null صريح عند فك الارتباط بدل إسقاط الحقل. تحفظ الواجهة revision التي قرأتها صراحةً ولا تعتمد أحدث revision في cache مشترك أثناء بقاء بياناتها قديمة. استجابة API تحمل revision الجديدة؛ المالك يعيد التحقق من قابلية التحرير تحت المعاملة.

أضيفت أرشفة صريحة ACTIVE/ARCHIVED بلا حذف. يرفض المالك أرشفة وحدة يرتبط بها أي برنامج أو أطفال، أو حرم ترتبط به برامج/وحدات، بما يشمل المراجع المؤرشفة. لا cascade ولا فقد معرفات. فحص البرامج يشترط campus/unit ACTIVE للمالك نفسه. الأب محفوظ من خريطة الجامعة فقط؛ يرفض القسم كأب والدورات واختلاف الحرم والأب المؤرشف. تبقى الجامعة المنشورة غير قابلة للتحرير الهيكلي، وREADY_TO_PUBLISH تعود للمراجعة؛ لا ظهور عام للمسودات.

الفحوص: 47 اختبارًا خفيفًا ناجحًا في خمسة ملفات، تتضمن قبول البرنامج الذري القائم، canonical geography، قوائم معرفات المالك، رفض الأب الخارجي ودورة في عقد محفوظة، فك الارتباط، حماية البرامج من الأرشفة وstale revision تحت FOR UPDATE. فحص الأنواع بلا emit ناجح؛ ESLint المحدد صفر أخطاء و4 تحذيرات قائمة؛ persistence 281/281 وsource architecture وdiff-check ناجحة. لا اختبارات شاملة أو build.

الاختبارات ببدائل تثبت الأوامر وشروط المصدر ولا تثبت عزل PostgreSQL الفعلي؛ يلزم browser/API/DB مع محررين متزامنين وإعادة تحميل القوائم/البرامج على بيانات اختبار معزولة. لم تُقرأ بيانات تشغيلية أو تُطبق ترحيلات؛ لا schema جديد أو SQL تاريخي. متطلبات runtime السابقة قائمة. التراجع بإخفاء الأرشفة والتأليف الجديد مع إبقاء IDs والصفوف. التالية B10c.
