# تبسيط تحرير المنح — 2026-10-29

طلب المستخدم هو تحرير المنحة من بطاقات معلومات واضحة، دون الحقول التقنية الفارغة.

- المعلومات الأساسية: الاسم، المانح، بلد الدراسة، السنة عند وجودها، لغة الدراسة، الموعد، الدرجة، نوع التمويل. لكل بطاقة مسار تعديل؛ تعديل الدرجة يفتح محرر العلاقات المعتمد.
- النبذة: زر تعديل مباشر مع حفظ المراجعة نفسه.
- التمويل: تبقى حقول التمويل والمبلغ والعملة؛ المزايا بطاقات منفصلة داخل مجموعات مسماة يمكن إضافتها وإعادة تسميتها ونقل المزايا بينها. حذف مجموعة يبقي مزاياها ضمن المجموعة العامة؛ حذف ميزة نفسها إجراء مستقل قبل الحفظ.
- الدرجات والتخصصات: مجموعة لكل درجة مع إضافة تخصص لها؛ حذف الدرجة يبقي التخصصات غير موزعة دون مسح المراجع. تظل أزواج البرامج الممولة المثبتة مستقلة عن التجميع التحريري.
- الأهلية والمستندات: نصوص قابلة للتحرير؛ تعليمات المستند الموجودة تبقى متاحة، ولا تُعرض حقول نوع المستند أو معرّفات الاختبارات الفارغة.
- المصادر: أقسام وروابط قابلة للإضافة والحذف؛ استخدام الرابط يربطه عند الاختيار بحقل التقديم أو الإعلان الرسمي أو الموقع أو المصدر. أدلة الاستيراد الأصلية للقراءة ضمن لوحة مطوية.

تُخزن مجموعات التمويل والروابط في `metadata.adminPresentation` عبر PATCH الموجود، دون مخطط جديد. تبقى حقول المصدر والبيانات المشروطة الحالية عند تحرير بيانات أخرى. تستمر شروط DRAFT والصلاحيات وIf-Match وسبب التعديل والتحقق من إعادة القراءة. الحفظ لا ينشر المنحة. لا ترحيل أو تعبئة أو حذف بيانات أصلية آلي في هذه الدفعة.

التحقق: 213 حالة للمنح، و6235 حالة Vitest عامة (8 متجاوزة)، وبناء كامل ثم إعادة بناء الإدارة بعد آخر تعديل، وفحص TypeScript وESLint وجودة المصدر. اختبار المستودع يثبت إعادة قراءة المجموعات من التخزين الحالي مع حفظ أدلة المصدر، باستخدام بديل اختباري دون اتصال بالقاعدة الأصلية. تشغيل الواجهة على القاعدة الأصلية وإثبات التفاعل بعد المصادقة يسجلان منفصلين؛ HTTP وحده ليس إثباتًا للتفاعل.
