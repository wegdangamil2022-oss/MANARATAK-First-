# ربط دفعة الجامعات المحدودة بمحتواها

المشكلة المثبتة: معرّف UniversityImportChangePlanner كان stage/artifact فقط؛ اختيار صفين أو المصنف كله يعطي المعرّف نفسه، ويمكن أن تُفسر دفعة مختلفة على أنها إعادة طلب ناجحة.

أصبح المخطط يختم محتوى الخطة ببصمة SHA256 لـJSON مرتب المفاتيح بعد توحيد إسقاط JSON، دون حقلي changeSetId وplanHash. يدخل في البصمة stage والمصدر والتغييرات المختارة وتسلسلها وحقولها وإيصالات provenance وأخطاء التحقق وdatabaseWrites. المعرّف الجديد stage:artifact:planHash؛ تغيير الاختيار أو الإسقاط يغير الهوية. ليست هذه البصمة توقيعًا بشريًا أو اعتماد مصدر.

يفحص application executor وبوابة Prisma الختم قبل فتح المعاملة. البوابة ترفض أيضًا خطة فارغة أو بأخطاء أو databaseWrites غير صفري. يحتاج CLI commit قيمة UNIVERSITY_IMPORT_APPROVAL_PLAN_HASH مطابقة إضافة إلى بوابات التفويض والتعافي والبيئة الموجودة. وضع inspect يتحقق من الختم بلا اتصال. الخطة القديمة غير المختومة تحتاج إعادة تخطيط واعتماد قبل تطبيق جديد؛ مسار التعويض للإيصالات التاريخية يبقى بمعرّفها القديم بعد التفويض. لا migrations ولا إعادة تسمية إيصالات سابقة.

اختبار RED أثبت تطابق معرّف اختيارين مختلفين قبل الإصلاح. بعده نجح 23 فحصًا في ملفي المخطط والبوابة، ومنها رفض العبث قبل فتح المعاملة، واستمرار المنع والصلاحيات ومسارات المالك السابقة. بُنيت application ثم infrastructure. lint دون أخطاء؛ بقي تحذير any سابق في fixture مخطط الجامعة دون تغييره. جرد البيئة يُولد ويُفحص للمتغير الجديد. هذا التسليم يثبت المصدر؛ تجربة PostgreSQL الجديدة تأتي بإيصال منفصل دون ادعاء قبول الهدف المدار.
