## Reviewable implementation choices and operational limits

Governance, review and published revision snapshots live in owner-controlled `_career` metadata in the existing JSON columns; client schemas cannot submit those fields. No new database schema was necessary in this batch. Review and verification evidence also enter transactional events, so replacing current evidence does not erase its event record. Fine-grained capabilities are registered in the central permission catalog and must be assigned through IAM before runtime use; `admin:careers:manage` alone does not grant author/review/PII capabilities.

Legacy VERIFIED employers and PUBLISHED jobs without the new independent evidence do not gain trust automatically. An author must edit/attest the record and another reviewer must verify/review it before it is exposed again. Salary blobs with only a legacy free-text label are not certified numeric salaries and must be cleared or corrected through editing. Consent is owner-granted until revoked; network audience is separately enforced. The current CV picker consumes trusted PDF assets already available in the student's EAP account; this batch does not create an upload/storage authority or promise live file ingestion.

This is the requested basic operating surface, not a full recruitment ATS. Expanded analytics/export dashboards, employer-facing interview calendars and advanced ranked/skill/salary-range search remain enhancements, not verified capabilities. Database expression-query performance/index tuning, source freshness thresholds, historical dedup reconciliation, IAM policy deployment, application retention/erasure policy, real outbox/worker/notification consumers and accessibility/full locale parity require the post-section-28 environment. No existing runtime acceptance result was reused for these changes.
