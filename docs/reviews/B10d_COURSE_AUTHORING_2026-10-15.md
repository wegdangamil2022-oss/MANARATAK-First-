# B10d — تأليف بنوك الأسئلة والمسارات وترتيب المسودات

الحالة SOURCE_VERIFIED؛ runtime/database PENDING؛ deployment NOT_PERFORMED. بدأت بعد توثيق ودفع B10c في 73ccbc83. [المواصفة](../remediation/specs/B10d_COURSE_AUTHORING_CONTRACT_2026-10-15.md) تحدد المالك والحالات والصلاحيات والنسخ والأثر العام قبل UI، ونُفذت بنوك الأسئلة ثم المسارات ثم ضوابط الترتيب والأرشفة.

## التنفيذ

- بنوك الأسئلة: واجهة ضمن تفاصيل الدورة لإنشاء بنك مسودة وتعديل عنوانه، وإضافة وتعديل سؤال إجابة قصيرة ومفتاحه الإداري، وأرشفة السؤال/البنك عبر أوامر المالك الحالية. بقية أنماط الأسئلة وعقودها القائمة بقيت كما هي؛ لا تغيير في التقييم اليدوي/الآلي. يعرض المحرر البنوك المملوكة للدورة فقط؛ يرفض الخادم بنكًا أو quiz مؤرشفًا/خارجيًا عند ربط سؤال، وعنوان بنك أو سؤال فارغًا، وأرشفة بنك له أي مرجع سؤال حتى لو مؤرشفًا. لا تمحى المراجع لتمكين الأرشفة.
- مسارات التعلم: مساحة في قائمة الدورات لإنشاء DRAFT، واختيار دورات داخلية ببحث وصفحات من المالك، وتحرير العنوان والوصف والإلزام والترتيب والمتطلبات ومنطق الإكمال. أضيف PATCH لمسودة المسار فقط تحت CourseAdminCommandUseCases؛ يحفظ LearningPathVersion جديدة ولا يعيد كتابة تاريخ العضويات. تعديل العنوان وحده يحفظ الدورات إذا غاب حقل courses؛ إرسال [] قرار إزالة صريح. ترفض الحالات المنشورة/الجاهزة/المؤرشفة، والدورات الخارجية والمعرفات المكررة والدورات في المتطلبات والمتطلب اللاحق الذي يجعل الترتيب الإلزامي مستحيلًا. الحد 100 دورة للمسار، وقوائم المسارات صفحات bounded بحد 50 من adapter و20 في UI.
- حفظ flags الترتيب ومنطق الإكمال والعنوان والوصف داخل snapshots الجديدة؛ قارئ نسخة التسجيل يفضلها على الجذر المتغير. النسخ القديمة التي لا تحمل flags تستخدم سلوك التوافق القائم؛ المسارات المنشورة/المؤرشفة لا تقبل التحرير، ولا يوجد أمر لإعادتها لمسودة، فلا يعاد استنتاج أو كتابة تاريخها. يلزم تضمين بيانات قديمة في rehearsal التشغيلي.
- ترتيب/إزالة المسودة: ضوابط الوحدات والدروس ترسل permutation لكل IDs في نطاقها، مع If-Match من النسخة المعروضة وسبب وفاعل. الإزالة تستخدم archival الحالي؛ الوحدة تؤرشف عناصرها، والدرس اختباراته، والاختبار/السؤال يحتفظان بمعرفاتهما. CourseVersion المنشورة ونسخة التحاق الطالب لا تتغير. لا SQL delete جديد ولا تغيير في محاولات الطلاب.
- RBAC القائم admin:courses:manage عند تركيب router وفي UI؛ كل أمر تعديل يمر عبر معاملة الأعمال والتدقيق وoutbox مع قفل إصدار المالك. النشر يحافظ على مسار المالك المستقل. لا صلاحية أو قاعدة موافقة مخترعة.

## الفحوص

**53 اختبارًا ناجحًا في سبعة ملفات**، إضافة إلى **8 اختبارات B10b موجهة ناجحة** مرتبطة بتصحيح فاحص المصدر أدناه. شملت رفض مراجع بنك مؤرشف، حماية المنشور، إعادة ترتيب بمحاولتين متزامنتين ونجاح واحدة ورفض stale للأخرى، حفظ IDs، graph غير صالح، عضوية DRAFT، نسخة تاريخية وflags، النسخة المثبتة للطلاب ومفاتيح الإجابات الأصلية، archival بلا فقد IDs، وHTTP/UI بإصدار وسبب وصلاحية. الاختبارات تستخدم بدائل ولا تثبت أقفال PostgreSQL الحقيقية.

فحص الأنواع بلا emit عبر .b10-typecheck.json ناجح؛ ESLint المحدد صفر أخطاء و7 تحذيرات any في الملفات القائمة. فواحص المصدر السبعة نجحت: persistence 281/281، assets 32/4، architecture، WP8، P3 57/57، WP12.9، P9 97/97. source quality وsecret scan وdiff-check ناجحة. لا build ولا اختبارات شاملة.

كشف الفحص النهائي شرط P9-UNI-005 النصي المتقادم: توقع where للجامعة بلا status حرفيًا، بينما B10b شدده إلى ACTIVE. حُدث الشرط ليطلب الصيغة الأشد، دون حذف assertion أو تخفيفه؛ B10bStructure.spec يثبت معرف المالك والحالة في استعلام البرنامج، وأعيدت حالاته الثماني. هذا تصحيح فاحص مدعوم بسلوك، وليس إعادة تنفيذ B10b أو إخفاء تراجع في المالك.

## المتبقي والتراجع

لا schema أو ترحيل جديد، ولا تعديل SQL تاريخي، ولا بيانات تشغيلية أو بريد/دفع أو worker حقيقي. يلزم قاعدة معزولة لإثبات FOR UPDATE وversion uniqueness وفشل audit/outbox وتنافس محررين، ثم browser→API→DB لبنوك الأسئلة/المسارات/سحب نشر الدورة والأرشفة مع نسخة تسجيل طالب قديمة. متطلبات runtime السابقة وNode 22 المعتمد مستمرة. لا ادعاء deployed أو production ready.

التراجع بإخفاء المساحات الجديدة مع إبقاء النسخ المنشورة وسجلات التقدم. اكتملت B10a–B10d على مستوى المصدر بالتسلسل وعلى فرع العمل فقط. التالية B11، خارج نطاق هذه الجولة؛ لم تبدأ.
