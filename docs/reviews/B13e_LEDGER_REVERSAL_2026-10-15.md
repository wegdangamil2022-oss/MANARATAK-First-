# B13e — عكس قيد يدوي ومراجعة الموافقة

خط الأساس: 0c84a622a25deb020c99c60753ae830e54cb4fe8. تنفيذ مستقل مع فحوص مصدر محددة؛ لا تشغيل مالي فعلي.

أضيفت قراءة قيد بمرجعه عبر مالك المالية وGET بصلاحية المالية القائمة وno-store. يُظهر التبويب القيود المقروءة وقيد العكس إن وجد، ولا يحررها. تسمح الواجهة بطلب موافقة MANUAL_LEDGER_REVERSE لقيد MANUAL_ADJUSTMENT قائم غير معكوس، ثم تنفيذ المنشئ بموافقة حقيقية مرتبطة بمعرفه الداخلي وسبب مدقق. الخادم يطبع الهدف إلى معرف المالك ويكوّن payloadHash؛ الواجهة لا تختار quorum أو maker أو سياسة أو checkers.

أضيفت قرارات المراجعين في تفاصيل الموافقة القائمة، بصلاحية approval:decide وصلاحية الإجراء الذي تفرضه سياسة الخادم. شرط maker/checker والمراجعين المختلفين والمهلة والاستهلاك بقي كما هو. أُصلح replay لإنشاء الموافقة وقرارها وعكس القيد باستخدام FinanceCommandRecord ضمن المعاملات القائمة. التحقق من أهلية checker انتقل من فحص تطبيق سابق إلى معاملة المالك بعد replay، والهوية تطابق الفاعل المصادق. قرار الموافقة يلزم إصدارًا ويحدّثه بشرط الإصدار. عكس نفس النية لا يستهلك الموافقة أو ينشر القيد مرتين؛ تغيير الموافقة أو السبب بنفس المفتاح مرفوض. fallback للسجلات القديمة يتحقق من الممثل والهدف دون اختراع مرجع موافقة مفقود.

API العكس يلزم reason بطول 3–500 مع approvalId؛ هذا توسع موثق للعقد السابق الذي كان يقبل approvalId وحده. قرار الموافقة يلزم expectedVersion. الإنشاء يبقي المهلة والخوارزمية لدى الخادم؛ إعادة المحاولة تحفظ الموافقة الأولى ولا تمدد مهلة قديمة. لا سياسة موافقة جديدة ولا ledger يتغير من الواجهة.

فحص V8 مرة واحدة على أجسام المصدر وبدائل ذاكرة صريحة: 9/9 PASS، منها append-only واتجاه معاكس مطابق، replay مرة واحدة، رفض تغيير الموافقة أو عكس جديد أو قيد مالك، quorum القائم لمراجعين مختلفين، رفض المنشئ كمراجع وduplicate checker وانتهاء/استهلاك الموافقة.
