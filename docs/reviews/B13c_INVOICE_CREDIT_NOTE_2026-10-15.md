# B13c — الإشعار الدائن

خط الأساس: 3b610595cf71e8c56fd1b6c18d4bf8d3ebc19038. تنفيذ مستقل؛ typecheck وUI/HTTP والتشغيل غير مثبتة في هذه الجولة.

أضيف نموذج إشعار دائن في تفاصيل الفاتورة بعملة ومنازل الفاتورة وسبب مطلوب، عبر intent الإرسال القائم نفسه (key/body/version ثابتة، منع التوازي، retry مطابق). API يلزم expectedVersion وصلاحية invoice:manage. لا استرداد عند مزود ولا تغيير سياسة موافقة.

أُصلح المالك: durable replay قبل فحص حالة CREDITED أو الإصدار؛ النية تربط المبلغ والسبب والإصدار بالطلب؛ النتيجة محفوظة في FinanceCommandRecord ضمن المعاملة نفسها. استمر تحقق المستحق والعملة والمنازل والحجوزات والقيد الدائن append-only والتدقيق/outbox. تحقق التطبيق أصبح مستقلاً عن الحالة المتغيرة، كي لا يمنع replay بعد ائتمان كامل.

فحص خفيف واحد لجسم معاملة المصدر ببدائل V8 أعطى 3 حالات مؤكدة (إصدار مفقود/صفر/سبب مفقود)، وخطأين في تجهيز البديل لغياب binding استيراد InvoiceStatus؛ 4 نتائج أخرى سُحبت من النجاح لأنها واجهت الخطأ نفسه. المصدر نفسه يستورد enum أصلًا. وُثق تصحيح تجهيز الفحص ولم يُعد تشغيله التزامًا بطلب المستخدم عندما لا تتجاوز الأخطاء اثنين. [الدليل الصريح](evidence/b13c-credit-light-checks-2026-10-15.json). لا تُعلن الحالات غير المتحققة ناجحة.

تعطل exec-server يمنع TypeScript/Vitest/الفواحص المحلية؛ القراءة والتحرير والدفع عبر GitHub. لا build ولا DB أو مزود أو تأثير مالي. قبول هذه الخطوة مراجعة مصدر محدودة، وليس SOURCE_VERIFIED شاملًا. يلزم لاحقًا فحص replay بعد الائتمان الكامل وتغيير النية والإصدار/العملة/المبلغ ضمن معاملة PostgreSQL معزولة وتجربة UI/HTTP. التراجع بتعطيل النموذج؛ لا حذف قيد أو إشعار سابق. التالي المحفظة.
