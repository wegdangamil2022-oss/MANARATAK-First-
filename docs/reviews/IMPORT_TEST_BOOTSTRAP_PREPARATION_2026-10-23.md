TOEFL وIELTS ضمن توصيات الاستبدال التاريخية. عقد `prepareInternationalTestImport` يفرض `APPROVE_UPDATE` عليها؛ تغييرها إلى create أو تغيير manifest لتجاوز الحارس غير مسموح بهذا التقرير. يلزم حسم دعم أول استيراد إلى هدف مستقل ضمن عقد المالك، مع دليل غياب الهدف ومعاينة حية. المصدر الخام والمقارنة التاريخية محفوظان.

المتطلبات الفعلية قبل الكتابة، حسب ترتيب التبعية:

1. تجهيز هوية تطوير موثقة عبر Identity/Authorization owner، بحالة الحساب والبريد والصلاحيتين `admin:imports:manage` و`admin:international-tests:manage`. `PrismaInternationalTestImportChangeGateway.assertActor` يفحص ذلك حتى عند preview؛ اسم مشغل مفوض في JSON لا يقوم مقام السجل. هذه تبعية حساب من P12 تُجهز مبكرًا، دون ادعاء تشغيل API/Admin.
2. مراجعة المزود الرسمي لكل اختبار ثم `InternationalTestUseCases.upsertProvider` الذري؛ حفظ UUID الناتج فعلًا. لا مزود وهمي أو إعادة استعمال UUID من مشروع قديم.
3. `familyId` اختياري في `InternationalTestImportChangeSet.coreSchema`. لا ننشئ عائلة مباشرة بـPrisma ولا نخمن UUID لإزالة نقص غير إلزامي؛ يراجع تنظيم العائلات عند الحاجة عبر عقد مالك مثبت.
4. حسم التاريخ مقابل الهدف، ثم إنشاء دفعة 1–5 بهويات فعلية وبصمات مصادر وpreviewHash، واعتماد نطاق التطبيق ودليل recovery حديث. لا تخفيف assertion أو guard قائم، ولا استخدام دور قاعدة مرتفع لتنفيذ الفحص.
