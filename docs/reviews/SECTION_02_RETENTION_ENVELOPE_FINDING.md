# 02.7 — حدود payload غير القابل للتعديل وretention envelope

حالة: Finding معماري موثق؛ ليس ADR معتمدًا، ولا تغيير تصميم أو قاعدة بيانات.

السلوك الموجود: `PrismaAuditRecordRepository` يضيف أحداث التدقيق ولا يملك API لتغيير محتواها. `PrismaAuditRetentionGateway` يغير الحقول التشغيلية `lifecycleState`, `retentionProcessedAt`, `retentionClaimToken`, `retentionClaimUntil`. تجميد قضية التحقيق يُعاد التحقق منه تحت القفل نفسه؛ لا يغير السجل الأصلي أو الملاحظات التاريخية. حارس إعداد الاحتفاظ الجديد يطبق على INSERT فقط، ولا يعمل backfill.

القرار المطلوب من مالك المعمارية لاحقًا: اعتماد الخيار A، أي أن payload immutable بينما هذه الحقول operational envelope مسموح تعديلها؛ أو الخيار B بنقل الحالة التشغيلية إلى جدول مستقل وخطة نقل منفصلة. لا تدّعي صفحة Integrity مصادقة cryptographic على المحتوى ولا إثبات اكتمال التسليم. مدد الاحتفاظ إعداد إداري صريح؛ غياب القيمة يعني الاحتفاظ دون انتهاء مفترض.

لم يُشغّل retention sweep أو ترحيل أو تعديل قاعدة قائمة. الفصل بجدول جديد ليس شرط تنفيذ واجهات القسم الآن حسب الخطة، ولا ينبغي تطبيقه دون القرار المطلوب.
