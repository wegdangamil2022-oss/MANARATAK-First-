# B10c — إنشاء مسودات عبر المالك

الحالة SOURCE_VERIFIED؛ runtime/database PENDING؛ deployment NOT_PERFORMED. بدأت بعد إغلاق B10b في 5a963fde. [المواصفة](../remediation/specs/B10c_OWNER_DRAFT_CREATION_CONTRACT_2026-10-15.md) تحدد المالك والحالات والصلاحيات والمصدر والتكرار وDegreeLevel.

أضيف POST collection للجامعات والتخصصات عبر UseCases المالكة، مع manage guard ومخطط صارم وفاعل مصادق وسبب ومصدر HTTPS/SHA256. تُنشأ الجامعة READY_TO_REVIEW/NEEDS_REVIEW؛ التخصص معه profile معياري ونسخة وأقسام فارغة للمراجعة ومصدر، جميعها داخل المعاملة المدققة. IDs يولدها الخادم ويحفظها محول المالك لتطابق هوية سجل التدقيق مع السجل الحقيقي. يُخصص code بعد سقف الكتالوج؛ تستخدم إزالة التكرار خدمات المالك القائمة وقيد uniqueness الدائم، ولا fuzzy linking أو IDs من النصوص. لا تغيير في بوابات bulk import.

إنشاء المنح كان قائمًا؛ أُعيد استخدامه مع مصدر ADMIN_ENTRY/createdBy وpublicationStatus=DRAFT، وصار slug يضم المعرف العام لتفادي تصادم أسماء مع جهات مختلفة. API create يرفض حقول حالة النشر/actor غير المعروفة ويطبق manage guard صريحًا. لا تمنح نصوص الدرجة والدولة الموردة ربطًا معياريًا تلقائيًا؛ تُستكمل العلاقات من محرر المالك قبل النشر.

نموذج إنشاء محدود في قائمة كل مالك، بصلاحيته ورسالة مسودة خاصة ورابط بمعرف الخادم إلى محررها. تخصص جديد يختار DegreeLevel فعالة من مالك المرجع، والمجال الأكاديمي ببحث وصفحات. الجامعة تسمح ببيانات جغرافية ناقصة في المسودة ولا تحول اسم الدولة إلى ID. مصادر الجامعة تبقى مع officialSourceUrl/provenance حتى استكمال مراجعة المصدر، ولا تُحسب اعتمادًا.

DegreeLevel مستقل: الأكواد finite وسياسة المرجع القائمة وواجهته صاحبة الإنشاء والتعديل. لا حاجة لقدرة إنشاء درجة ضمن نموذج تخصص/منحة، ولا إضافة أكواد أو موافقة مفترضة. أي درجة غير قائمة تبقى قرار نطاق عند مالك المرجع، ولا تُختلق.

الفحوص: 40 اختبارًا ناجحًا في خمسة ملفات؛ owner create، رفض التكرار وغياب الفاعل/السبب، rollback ببديل معاملة عند فشل النسخة، درجة غير مطابقة، RBAC/API strict payload، وإرسال نموذج الجامعة إلى صاحب API وربط ID العائد. فحص أنواع admin/API وdependencies بلا emit ناجح؛ ESLint المحدد صفر أخطاء و25 تحذير any في الملفات القائمة. source architecture وpersistence 281/281 وsource quality وsecret scan وdiff-check ناجحة. لا build ولا اختبارات شاملة.

لا schema أو ترحيل جديد، ولا SQL تاريخي أو DB/مزود حقيقي. الاختبارات لا تثبت uniqueness/rollback في PostgreSQL: يلزم إنشاء متزامن بهوية واحدة في قاعدة معزولة، وفشل audit/outbox، وbrowser/API/DB مع صلاحيات ممثلة لإثبات عزل المسودة حتى المراجعة والنشر. جميع متطلبات runtime السابقة مستمرة؛ لا إعلان production ready.

التراجع بإخفاء نماذج الإنشاء، مع إبقاء المسودات والمصادر والنسخ. الحزمة التالية B10d.
