# إغلاق المرحلة 15 — منصة الطالب المؤسسية

## حالة المصدر

الحالة: `SOURCE_COMPLETE_RUNTIME_PENDING`

أصبحت منصة الطالب في المصدر مساحة شخصية حقيقية وليست صفحة تجريبية. أُنجزت العقود، التخزين، العزل الأمني، التركيب عبر BFF، واجهة الطالب العربية، واختبارات المصدر. لم يُشغّل اتصال PostgreSQL أو migrations أو seed أو Redis أو Google Studio أثناء التطوير المحلي.

## ما أُنجز

- دورة حياة مساحة الطالب: `INITIALIZING` و`ACTIVE` و`SUSPENDED` و`ARCHIVED`.
- Optimistic concurrency عبر `version` و`expectedVersion` لمنع ضياع تعديلات جهاز آخر.
- ربط كل طلب بهوية JWT ومنع الوصول إلى مساحة طالب آخر.
- تفضيلات اللغة والمنطقة الزمنية والمظهر وإمكانية الوصول.
- مصفوفة إشعارات ومركز خصوصية بإعدادات محافظة افتراضيًا.
- تخطيطات لوحة متعددة الأجهزة محفوظة كإعدادات فقط.
- محفوظات polymorphic دون نسخ بيانات الدورات أو المنح أو الجامعات أو الشهادات.
- مجموعات شخصية ومجموعة مفضلة افتراضية مع backfill للمساحات السابقة.
- سجل نشاط شخصي محدود إلى 50 عنصرًا وسجل بحث اختياري محدود إلى 25 عنصرًا.
- سجل رحلة append-only ولقطات immutable لإعدادات المساحة.
- Inbox يمنع تكرار أحداث الأنظمة السابقة وOutbox ذرّي لنشر تغييرات مساحة الطالب.
- إسقاطات إشعارات محلية لا تمتلك خدمة الإرسال نفسها.
- تركيب لوحة الطالب بالتوازي من التسجيلات التعليمية والشهادات والمحفوظات والإشعارات.
- عزل فشل كل بطاقة: تعطل مصدر واحد لا يسقط مساحة الطالب كاملة.
- إجراءات سريعة مشتقة من تقدم الطالب وشهاداته ومحفوظاته.
- واجهة عربية خضراء متجاوبة: الرئيسية، رحلتي، خزنتي، التحكم والخصوصية.
- حالات تحميل، فراغ، خطأ، تعطل جزئي، وتغذية راجعة عند الحفظ.

## حدود الملكية المحفوظة

- المرحلة 13 تظل مالكة للدورات والتسجيل والتقدم والإكمال.
- المرحلة 14 تظل مالكة للشهادات والقوالب والتوقيع والتحقق.
- المرحلة 05 تظل مالكة للأصول والصور والملفات.
- مرحلة الإشعارات تظل مالكة لإرسال البريد وPush؛ المرحلة 15 تحفظ التفضيل والإسقاط فقط.
- المرحلة 17 وحدها تحسب توصيات الذكاء الاصطناعي؛ المرحلة 15 جاهزة لعرض إسقاطاتها بعد تفعيلها.
- المرحلة 19 تظل مالكة للفواتير والدفعات.

## خطة التفعيل في Google Studio / بيئة التشغيل

### 1. قاعدة البيانات

1. ضع `DATABASE_URL` كسر بيئي في بيئة API والعمال.
2. خذ نسخة احتياطية من قاعدة البيانات قبل النشر.
3. شغّل `prisma migrate deploy` فقط عبر مسار النشر المعتمد.
4. لا تستخدم `prisma db push` في الإنتاج.
5. راجع إنشاء جداول المرحلة 15 والفهارس ومجموعة المفضلة للمساحات الموجودة.
6. شغّل `prisma generate` داخل صورة البناء قبل إقلاع API.

الـmigration المطلوب:

`20260824200000_phase15_enterprise_student_workspace`

### 2. الهوية والأمان

1. اضبط مفاتيح RS256 (`JWT_ACTIVE_KEY_ID` / private/public PEM) واجعل `ACCESS_TOKEN_TTL_SECONDS<=900`؛ refresh credentials opaque وعمر الجلسة يدار عبر `SESSION_TTL_SECONDS`.
2. تأكد أن `userId` داخل JWT هو نفسه `studentReferenceId` المعتمد لمساحة الطالب.
3. اختبر أن طالبًا لا يستطيع قراءة أو تعديل معرف طالب آخر.
4. اربط التعليق والأرشفة لاحقًا بصلاحيات إدارة المرحلة 23، ولا تفتحها لمسارات الطالب.

### 3. Redis والعمال

1. وفّر `REDIS_URL` منفصلًا حسب البيئة.
2. شغّل عامل Inbox لاستهلاك أحداث الهوية والتعلم والشهادات والإشعارات.
3. شغّل عامل Outbox بآلية retry وexponential backoff وDLQ.
4. اضبط مفاتيح cache بحيث تتضمن `studentReferenceId` دائمًا.
5. امسح cache الخاص بالطالب بعد تعديل الإعدادات أو المحفوظات.

الأحداث الأولى المطلوب ربطها:

- `StudentIdentityCreated`
- `CourseEnrolled`
- `CourseProgressUpdated`
- `CourseCompleted`
- `CertificateIssued`
- `CertificateRevoked`
- `InvoiceIssued`
- `PaymentCaptured`

### 4. الإشعارات والوقت الحقيقي

1. اربط `StudentNotificationProjection` بمستهلك أحداث خدمة الإشعارات.
2. احترم `notificationMatrix` قبل email أو push.
3. فعّل SSE أو WebSocket لتحديث البطاقات بين الأجهزة.
4. لا ترسل إشعارات الذكاء الاصطناعي ما لم يكن `allowPersonalization=true`.

### 5. الأصول

1. اربط `avatarAssetId` بمحلل أصول Phase 05 EAP.
2. اربط معاينات وملفات الشهادات عبر AssetId، لا عبر مسارات ملفات أو روابط خام.
3. اضبط روابط تنزيل موقعة قصيرة العمر للملفات الخاصة.

### 6. الرصد والتشغيل

أنشئ لوحات مراقبة وتنبيهات للآتي:

- زمن استجابة dashboard P50/P95/P99.
- نسبة فشل كل capability داخل BFF.
- عمق Outbox وعمر أقدم رسالة.
- تأخر Inbox وعدد الأحداث المكررة.
- cache hit ratio.
- تعارضات `STUDENT_WORKSPACE_VERSION_CONFLICT`.
- محاولات `STUDENT_WORKSPACE_ACCESS_DENIED`.

### 7. الاختبار التشغيلي بعد النشر

1. سجّل طالبًا جديدًا وتحقق من إنشاء المساحة والمفضلة مرة واحدة.
2. سجّل الطالب في دورة وتحقق من ظهورها في «رحلتي».
3. حدّث التقدم من جهازين وتحقق من اكتشاف تعارض الإصدار.
4. أكمل دورة وتحقق من وصول حدث واحد للسجل حتى مع إعادة تسليمه.
5. أصدر شهادة وتحقق من ظهورها في «خزنتي» ومن رابط التحقق.
6. عطّل خدمة الشهادات مؤقتًا وتحقق أن بقية اللوحة تستمر مع تحذير جزئي.
7. علّق المساحة وتحقق أن القراءة المسموح بها تعمل وأن جميع الكتابات تُرفض.
8. عطّل الاحتفاظ بسجل البحث وتحقق من عدم إنشاء سجلات جديدة.
9. اختبر العربية، RTL، الهاتف، لوحة المفاتيح، وقارئ الشاشة.

## ما يبقى Runtime فقط

- تطبيق migration على PostgreSQL الحقيقي.
- تشغيل Redis وBullMQ وDLQ والعمال الدائمين.
- ربط event bus الحقيقي ومفاتيح الموضوعات.
- تفعيل SSE/WebSocket ومزامنة الجلسات الحية.
- ربط EAP للتنزيل والصور الموقعة.
- ربط email/push providers.
- تفعيل إسقاطات توصيات Phase 17 بعد تنفيذها.
- اختبار pilot وقياس الأداء والسعة في بيئة Google Studio.

هذه العناصر ليست نقصًا في برمجة المرحلة 15؛ هي أعمال تفعيل بيئي تعتمد على الأسرار والبنية الحية وقاعدة البيانات، ولذلك تُنفذ عند تشغيل المشروع.
